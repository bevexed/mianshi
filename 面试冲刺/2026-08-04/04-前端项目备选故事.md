# 前端项目备选故事

主项目已经用 NestJS 证明后端深度。前端项目不要再堆技术名词，应分别证明：C 端现代架构能力、复杂业务建模能力。

## 项目一：Next.js 官网与云产品购买链路

### 60 秒版本

> 这是公司的产业互联网平台官网，既承载产品介绍和获客，也包含云产品在线选购和下单。项目使用 Next.js 16 App Router、React、TypeScript 和 Tailwind，数据层使用 Zustand 与 React Query。
>
> 我从 0 开发了云产品购买链路，包括购买页、版本和配置选购、折扣展示与结算，同时参与验证码和登录注册流程重构。技术上最需要取舍的是 Server/Client Component 边界、不同页面的渲染策略，以及交互型选购页面的状态归属。
>
> 交易链路里前端价格计算只负责即时展示，最终价格必须由后端重新计算和校验；状态层面则把服务端缓存交给 React Query，把用户当前选购和 UI 状态留在客户端，避免把两类状态混在一起。

### 三个追问钩子

#### RSC 与 Client Component 怎么分？

> App Router 默认是 Server Component。需要浏览器 API、事件或 hooks 的叶子组件再加 `'use client'`，边界尽量下沉，否则导入链会扩大客户端 bundle。RSC 的核心收益不只是服务端先出 HTML，而是服务端组件代码和依赖不进入浏览器 JS。

#### 渲染策略怎么选？

> 产品介绍这类人人相同、变更不频繁的内容适合静态生成或按需再验证；带用户态的页面需要动态渲染；选购配置的高交互部分在客户端完成。选择依据是个性化程度、更新频率、SEO 和可接受陈旧时间，不是全站只用一种策略。

`【需本人确认】` 实际使用的 SSG/ISR/SSR/CSR 页面和 `revalidate` 配置。

#### 前端为什么可以算价格？

> 前端计算是为了交互即时反馈，不能作为交易真相。下单时后端必须根据商品、套餐和优惠规则重算，前端提交的金额只能作为展示信息或校验线索。金额用整数最小单位或十进制定点库处理，避免浮点误差。

`【需本人确认】` 当前系统是否确实由后端重算价格；如果没有，应诚实说明这是回看后发现的风险。

### 其他可能追问

## 项目二：复杂运营后台与表单状态

### 60 秒版本

> 这是产业信息平台的运营管理后台，使用 umi/max、React、TypeScript 和 antd，也是微前端子应用。我主要负责内容管理域的产品、套餐、套件、版本、指标和订阅策略，以及订单支付域的一部分功能。
>
> 这个项目最难的不是框架，而是把层层嵌套的业务配置翻译成运营可以理解、修改且不容易出错的表单。我的处理思路是先按用户操作频率拆分表单，再明确每类状态的权威来源：字段值和校验归 Form 实例，服务端数据归请求缓存，派生值现场计算，跨步骤草稿才进入外部 store。
>
> 我最后形成的方法论是，同一份数据只保留一个权威来源。很多复杂表单 bug 都来自 Form、组件 state 和缓存里各存一份，某条路径只更新了其中一个。

### 三个追问钩子

#### 嵌套表单怎么拆？

> 表单结构要反映业务模型，但不应把后端嵌套 JSON 原样铺给运营。我会按操作路径分组，把动态数组交给 `Form.List`，只在真实存在可配置 schema 时做元数据驱动，不为了“通用”提前制造一套表单引擎。

#### 版本切换怎么恢复数据？

> 先定义产品规则：切走时未保存内容是丢弃、暂存还是提示；切回时恢复服务端初始值还是草稿。`initialValues` 只在首次挂载生效，异步切换通常需要 `setFieldsValue`、重挂载或版本草稿。选择哪种取决于用户是否高频跨版本编辑。

`【需本人确认】` 实际使用的是重置确认、版本草稿还是其他方案。

#### 权限按钮怎么做？

> 后端返回权限码，前端用权限组件或 hook 控制菜单和操作按钮。但前端隐藏只改善体验，不构成安全边界；接口必须再次鉴权，并避免只凭前端提交的用户或资源 ID 判断权限。

### 为什么这个项目适合 8 年经验表达

不要说“做了很多 CRUD”。重点说：

> B 端复杂度主要来自业务模型和状态变化，而不是框架新旧。我的价值是把模型、操作路径、状态权威来源和异常恢复先讲清，再决定组件如何拆分。

## 如何选择项目

- 问 C 端、SEO、性能、React/Next.js：讲项目一。
- 问复杂业务、表单、状态管理、B 端架构：讲项目二。
- 问 Vue：先回答 Vue 本身，再说明两套项目体现的状态边界、组件拆分和性能原则可以迁移；不要用 React 项目假装 Vue 项目。
- 问工程化或移动端：再从现有 H5/小程序经历补一个短例子，不主动增加第三个长故事。
