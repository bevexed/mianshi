# 自我介绍

不要逐字背。记住五个锚点：**8 年前端 → React/Vue/TS → 复杂前端 → NestJS 全链路 → 为什么匹配**。

## 60 秒版本

> 我有 8 年前端开发经验，核心技术栈是 React、Vue 和 TypeScript，做过 Next.js、微前端、H5、小程序以及前端工程化建设。
>
> 最近一段时间我的工作范围逐渐扩展到全栈。我从 0 到 1 负责过一个基于 NestJS 的数据采集服务，使用 BullMQ、Redis、MySQL 和 Playwright，部署涉及 Docker 和 K8s。项目里我重点处理了任务编排、幂等、失败重试、断点恢复、并发控制和线上问题排查。
>
> 我的优势是前端交付能力比较成熟，同时已经能够处理 Node.js 接口、数据库、异步任务和部署链路。这个岗位以前端和 Node.js 为主，又涉及 AI 能力接入，与我希望承担完整业务链路的发展方向比较匹配。

### 说完后停住

不要马上补 Java、MongoDB 或所有项目细节。让面试官从 NestJS、Vue 或复杂前端中选择追问。

## 30 秒版本

> 我有 8 年前端经验，主要使用 React、Vue 和 TypeScript，做过 Next.js、微前端、H5、小程序和工程化。最近我从 0 到 1 负责过 NestJS 数据采集服务，实际处理了 BullMQ、Redis、MySQL、任务幂等、失败恢复和 Docker/K8s 部署。现在希望找一个前端能力占主导、同时能承担 Node.js 和完整业务链路的岗位，这也是我关注这个机会的原因。

## “你最近主要做什么？”

> 最近一部分工作是复杂前端和 Next.js 业务交付，另一部分是把能力扩展到 Node.js 服务端。我投入最深的后端项目是 NestJS 采集服务，从队列编排、数据库状态到部署排障都有实际参与。对我来说这不是离开前端，而是把原来只负责页面的一段扩展成完整链路。

## “为什么从前端转全栈？”

> 我不是为了弱化前端，而是在成熟前端能力的基础上补齐服务端能力。项目里很多问题只看页面解决不了，比如任务状态、接口边界、数据一致性和部署恢复。实际承担 NestJS 项目以后，我已经可以处理接口、数据库、异步任务和部署，所以希望找一个前端占主导、但允许我负责完整业务结果的岗位。

## “你更偏前端还是后端？”

> 当前能力结构仍然是前端更深，Node.js 后端已经有完整项目经验。我不会把两边说成完全同一深度。对这个岗位而言，我可以先稳定承担前端主线，也能接住 Node.js 接口、任务、数据库和部署工作，并继续把全栈深度补上。

## “为什么对这个岗位感兴趣？”

> 我看重的是它的职责组合：Vue 和 TypeScript 是我熟悉的前端范围，Node.js/NestJS 与我最近实际扩展的方向一致，同时 AI API 接入需要兼顾产品体验、服务端稳定性、成本和安全，这正好能发挥我从前端体验到后端交付的完整视角。
