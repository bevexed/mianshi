# 岗位画像与应对策略

## 岗位本质

从现有 JD 信息看，这不是 Java 全栈岗，核心组合是：

> Vue / TypeScript 前端 + Node.js / NestJS 服务端 + 数据库 + AI API 接入。

岗位会看重候选人是否能把一个 C 端或业务产品从页面、接口、数据一直交付到部署和排障。你的主线不应是“我什么后端都懂”，而应是“成熟前端能力之上，已经有真实的 Node.js 全链路经验”。

## 你的匹配项

- 8 年前端经验，React、Vue、TypeScript、HTML、CSS 基础和项目交付可以作为稳定底盘。
- 有 Next.js、微前端、H5、小程序与工程化经历，能覆盖 C 端、多端和复杂前端追问。
- NestJS 采集服务不是练习项目，涉及 BullMQ、Redis、MySQL、Playwright、幂等、重试、断点恢复和受控并发。
- 参与过 Jenkins、Docker、Harbor、K8s 构建部署与线上排障，可以讲完整交付链路。
- MySQL、Redis 有实际使用经验，能够讨论索引、事务、缓存、锁和任务状态。

## 主要风险及处理

| 风险 | 不好的答法 | 处理策略 |
| --- | --- | --- |
| JD 写 Vue，你最近项目偏 React/Next.js | 一开口全讲 React | 先证明 Vue 基础和迁移能力，再用 React/Next.js 项目证明复杂交付能力 |
| MongoDB 缺少深度生产经验 | 把“了解”说成“做过” | 讲文档模型与 MySQL 的选型边界，明确实际主力是 MySQL、Redis |
| Express/Koa 不是主生产栈 | 临时背源码 | 讲路由、中间件、异常和请求生命周期，说明生产主力是 NestJS/Fastify |
| AI API 项目证据可能不足 | 只说“调接口” | 主动讲 SSE、停止生成、上下文裁剪、重试降级、成本与安全 |
| 8 年经验对应 3–5 年岗位 | 表现得像降级求职 | 强调按职责和技术栈匹配，不以年限标签代替岗位判断 |
| Java 经验有限 | 主动说自己全栈 Java | 只在被问时说明能维护常规链路，然后转回 Node.js 优势 |

## 面试表达主线

### 一句话定位

> 我的核心优势是成熟的前端交付能力，同时已经实际承担过 Node.js 接口、异步任务、数据库和部署排障，目标是前端占主导、可以负责完整业务链路的全栈岗位。

### 回答顺序

1. 先给结论，不从背景讲起。
2. 用一个真实项目动作证明结论。
3. 说明为什么这样选，以及没有覆盖到哪里。
4. 停下来等追问，不一次塞入所有技术名词。

示例：

> 我在任务编排里把数据库任务记录作为业务事实来源，BullMQ 主要负责调度。这样即使写库后入队失败，也能通过扫描补偿；代价是系统仍需处理重复发布，所以 Worker 必须幂等。

## 预计面试顺序

1. 自我介绍与换工作原因。
2. 为什么从高级前端向全栈扩展。
3. NestJS 项目是否真实、独立程度如何。
4. Vue 3、TypeScript 与前端工程化。
5. MySQL、Redis、MongoDB 选型。
6. AI 助手或 AI API 接入设计。
7. Web 安全、性能、部署与排障。
8. 年限、技术短板、薪资和反问。

## 主动引导到这些区域

- BullMQ 为什么适合任务编排，而不是机械比较谁“更高级”。
- 幂等、重试、断点续跑、代理池竞态和任务状态机。
- 前端中“同一份数据只有一个权威来源”的方法论。
- 从页面到 Node.js 接口、数据库、Docker/K8s 的完整交付。
- AI 产品中的流式体验、错误恢复、成本与数据安全。

## 不要主动抛出的钩子

- 不主动说“我会 Java 安全审计”或“精通 Spring”。
- 不主动讲 MongoDB 生产调优、Kafka/RabbitMQ 实战。
- 不给无法核验的吞吐量、提升比例、日任务数和覆盖率。
- 不把采集描述成“绕过风控”；用“公开数据、受控并发、会话与验证稳定性、合规使用”表达。
- 不贬低前端，也不说“因为前端不好找工作才转全栈”。

## 卡住时的节奏

可以停一秒，然后说：

> 我先说结论，再结合我项目里的做法展开。

如果前提不明确：

> 这个问题和数据量、一致性要求有关。我先按单体业务服务、MySQL 和 Redis 已存在的条件回答，可以吗？

如果答错后意识到问题：

> 我修正一下刚才的说法。更准确的边界是……

主动修正比硬撑更可信。
