# Vue Router

## History 模式

```ts
const router = createRouter({
	history: createWebHistory(), // 或 createWebHashHistory / createMemoryHistory
	routes
});
```

| 模式          | URL                | 部署要求                                                     |
| ------------- | ------------------ | ------------------------------------------------------------ |
| HTML5 history | `/users/42`        | 服务端必须将未匹配路径回退到 SPA 入口，同时排除 API/静态资源 |
| hash          | `/#/users/42`      | hash 不发给服务端，静态部署简单，URL 不如 history 自然       |
| memory        | 不依赖浏览器地址栏 | SSR、测试或非浏览器环境                                      |

## 导航守卫

```ts
router.beforeEach(async (to) => {
	if (to.meta.requiresAuth && !(await hasSession())) {
		return { name: 'login', query: { redirect: to.fullPath } };
	}
});
```

| 层级     | API                                         | 用途                             |
| -------- | ------------------------------------------- | -------------------------------- |
| 全局     | `beforeEach`、`beforeResolve`、`afterEach`  | 通用授权、数据准备、埋点         |
| 路由记录 | `beforeEnter`                               | 特定路由的准入规则               |
| 组件     | `onBeforeRouteUpdate`、`onBeforeRouteLeave` | 处理复用实例参数变化、未保存编辑 |

Vue Router 4 优先通过**返回值**放行、取消或重定向。
三参数 `next` 仍兼容但容易重复调用或漏调，新代码应避免。
`afterEach` 是 hook，不能取消已确认导航。

## 授权边界

前端守卫只能改善交互和隐藏不可用界面，**不是安全边界**。
后端必须对每个受保护资源做身份认证和授权。

## 路由参数与组件复用

`/users/1` 切到 `/users/2` 时，Vue Router 通常复用同一组件实例，
所以 `onMounted` 不会重新执行。可以：

```ts
watch(
	() => route.params.id,
	(id) => loadUser(String(id)),
	{ immediate: true }
);
// 或 onBeforeRouteUpdate
```

## 懒加载与失败

```ts
const routes = [{ path: '/reports', component: () => import('./views/Reports.vue') }];
```

路由懒加载能拆分初始 bundle，但分块不是越细越好。
应处理加载态、错误、新版发布后旧 chunk 失效，并按业务需求设计预取。
