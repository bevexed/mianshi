# Vue 2 与 Vue 3 差异

> Vue 2 已于 2023-12-31 结束官方支持。新项目应使用 Vue 3；
> 了解 Vue 2 的主要价值是维护存量系统和设计迁移路径。

## 核心差异

| 维度          | Vue 2                                | Vue 3                                                 |
| ------------- | ------------------------------------ | ----------------------------------------------------- |
| 响应式        | `Object.defineProperty` 劫持已有属性 | Proxy 处理对象，ref 用 getter/setter                  |
| 新增/删除属性 | 通常需 `Vue.set` / `Vue.delete`      | Proxy 可跟踪常见新增/删除操作                         |
| 数组索引/长度 | 直接赋值有检测限制                   | 可跟踪                                                |
| 逻辑组织      | Options API、mixins 为主             | Composition API / composables，也继续支持 Options API |
| TypeScript    | 可用，但 Options API 推断边界较多    | 核心用 TypeScript 重写，Composition API 推断更自然    |
| 根节点        | 组件通常要单根                       | 支持 Fragment/多根节点                                |
| 应用实例      | 许多 API 是全局的                    | `createApp()` 隔离不同应用配置                        |
| 状态库        | Vuex 3                               | Pinia 是新项目的官方推荐                              |

Vue 3 **不是改成类组件**。它的主要新模型是函数式 Composition API，
`<script setup>` 是单文件组件的编译期语法糖。

## Composition API 解决了什么

- 把同一业务关注点的 state、computed、watch 和方法放在一起，
  不再被 `data` / `methods` / `computed` 拆散。
- 用 composable 显式复用逻辑，避免 mixin 的命名冲突、隐式来源和依赖不清。
- 通过普通函数和泛型获得更好的 TypeScript 推断。

```ts
export function useOnlineStatus() {
	const online = ref(navigator.onLine);
	const update = () => {
		online.value = navigator.onLine;
	};

	onMounted(() => window.addEventListener('online', update));
	onMounted(() => window.addEventListener('offline', update));
	onUnmounted(() => window.removeEventListener('online', update));
	onUnmounted(() => window.removeEventListener('offline', update));

	return readonly(online);
}
```

## 编译期优化

- **静态提升**：不会变的 vnode/属性提到渲染函数外复用。
- **Patch Flag**：编译器标记节点只有文本、class 或特定 prop 会变，
  运行时只比较已知的动态部分。
- **Block Tree**：对动态节点建立扁平跟踪，减少逐层遍历。

## 迁移检查项

1. 先升到 Vue 2.7 的最终线，清理已废弃 API 和旧插件。
2. 盘点 UI 库、Router、Vuex、测试工具与自定义指令的兼容性。
3. 重点检查 filters、`.sync`、事件 API、渲染函数和生命周期命名变化。
4. 分模块迁移并配合回归测试，不要把主版本升级和大规模业务重构捆绑。
