# Vue 3 Diff 与编译优化

## 前置判断

- vnode 类型和 key 都一致时，才可复用同一节点并继续 patch。
- 类型或 key 不同时，旧子树卸载、新子树挂载。
- 比较主要在同层子节点中进行，key 用于识别节点身份。

## Vue 3 keyed children 的核心流程

1. **从头同步**：新旧序列开头可复用就向后 patch。
2. **从尾同步**：末尾可复用就向前 patch。
3. **一方已经遍历完**：批量挂载或卸载另一方剩余节点。
4. **处理未知中间段**：
   - 为新子节点建立 `key -> newIndex` 映射；
   - 遍历旧中间段，找不到则卸载，找到则 patch 并记录新旧索引关系；
   - 从后向前遍历新中间段，挂载新节点、移动需要移动的旧节点。

## 最长递增子序列（LIS）做什么

中间段会得到一组“新位置对应的旧索引”。
这组序列中的 LIS 代表**相对顺序已经正确、可以保持不动**的节点；
其他可复用节点再移动。LIS 是为了减少 DOM 移动，不是用来查找节点。

```text
旧顺序：A B C D E
新顺序：A C D B E

新中间段对应旧索引：[2, 3, 1]
LIS 可取 [2, 3]，C/D 保持，移动 B。
```

## Vue 2 和 Vue 3 的常见区别

Vue 2 的双端对比围绕新旧头尾指针组合展开。
Vue 3 的快速 diff 优先处理相同前缀/后缀，
再用 key 映射和 LIS 处理未知中间段。

## key 的实践

- 使用稳定业务 ID，不要用随机数。
- 可增删、排序或包含局部状态的列表不要用 index 作 key。
- key 变化会让组件重新挂载，可用来显式重置状态，不应成为逃避状态设计的手段。
