# AI 检索工具案例

本案例描述一个让 AI 应用查询内部技术规范的通用系统，重点是上下文质量和权限，而不是某个具体组件库。

## 目标与非目标

目标：让模型在生成或评审代码时取得当前、相关、可引用的规范，并对产出进行结构化校验。

非目标：

- 不保证模型一定调用工具；强制规则由工作流或 CI 执行。
- 不把全部文档塞进上下文。
- 不让检索系统替代代码执行、类型检查和人工评审。

## 架构

```text
文档源 → 解析/切分 → 稀疏索引 + 向量索引 → 权限过滤
                                             ↓
AI Host ← MCP Resources / Tools ← 查询、融合、重排、引用
                                             ↓
                                  validate 工具 / CI 检查
```

Resources 适合读取已知文档，Tools 适合按查询检索或执行校验。Host 是否自动加入资源、是否让模型选择工具，取决于宿主能力和策略。

## 检索设计

- 按标题、组件或规则边界切分，保留父级路径、版本和来源。
- 精确组件名/属性使用关键词召回，自然语言需求使用向量召回，再融合去重。
- 权限过滤必须在返回内容前执行，索引和缓存 key 都包含租户/权限边界。
- 返回片段附带稳定 URI、版本和更新时间，便于引用和追溯。
- 证据不足时返回明确的低置信或无结果，不填充相似但无关的规则。

## 工具契约

```text
search_guidelines(query, framework?, component?, version?)
read_guideline(uri)
validate_code(code, framework, rulesetVersion)
```

每个工具用 schema 约束输入和结构化输出。`validate_code` 返回规则 ID、位置、严重级别和修复建议；是否阻断合并由 CI 策略决定，不能由模型临时判断。

## 更新与兼容

- 文档发布触发增量索引，删除和权限变化同样产生事件。
- 索引记录 embedding 模型和切分器版本；升级时建立新索引并原子切换。
- 规范版本与项目版本绑定，旧项目不应自动套用只适用于新版本的规则。
- 定期对账源文档和索引，监控更新延迟与失败队列。

## 评测

检索集覆盖精确名称、同义需求、版本差异、无答案和越权查询。指标包括 Recall@k、MRR、引用正确率、无答案拒答率和权限泄漏数。

生成层另外评估代码能否构建、是否使用存在的 API、关键规则违反数以及人工修改量。不能只用模型自评模型产出。

## 安全与治理

- 远程 MCP 使用认证、最小权限、来源校验、审计和速率限制。
- 文档内容可能含提示注入，作为不可信数据引用，不允许覆盖系统规则。
- 不返回令牌、内部密钥或无权查看的示例数据。
- 工具调用和检索日志脱敏，设置保留期和删除机制。

## 复盘问题

- 工具实际调用率低，是描述、Host 策略还是任务本身不需要？
- 检索命中但产出仍错误，是上下文过长、规则冲突还是模型能力问题？
- 质量提升是否抵消索引维护、延迟和调用成本？
- 团队是否能在没有原作者的情况下更新规则与评测集？
