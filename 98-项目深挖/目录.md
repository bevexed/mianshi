# 98-项目深挖 · 目录

本章直接服务于个人求职：把真实项目经历整理成可核验的项目自述、技术决策、追问和复盘。
技术原理章节保持通用，但这里允许保留真实公司、客户、项目和个人贡献上下文；不能为了“通用化”抹掉简历证据链。

> 项目材料以 [简历带项目.md](../../jianli/简历带项目.md) 为事实来源之一。
> 简历、代码和线上数据不一致时，以可验证证据为准，不能自行补数字。

## 使用原则

1. 先准备每篇的“一句话自述”和 60 秒版本，主动把追问引向熟悉区域。
2. `【需确认】` 必须回到代码、监控、工单或同事记录核实，不能编造规模、指标和职责。
3. 明确区分团队成果与个人贡献，用“我负责 / 我参与 / 团队完成”表达责任边界。
4. 每个优化都说明基线、约束、方案、验证方法和副作用，不用技术名词代替决策依据。
5. 对客户、账号、密钥、内部域名、个人隐私和未公开数据做脱敏；面试表达仍需遵守保密与合规要求。

## 个人方法论主线

可以把多段经历串成稳定的方法论，而不是逐篇背答案：

- 工程汇后台的“表单状态由谁持有”。
- 微信 H5 中 URL 参数与缓存优先级冲突，以及 URL 作为唯一来源。
- 采集服务中先画状态机，再实现任务流转和失败恢复。

前两类问题可收敛为“同一份数据只有一个权威来源”；后一类体现“先定义状态和非法转换，再写流程代码”。
只有在真实项目材料能够支撑时才使用这些总结。
