# 知识库 AGENTS.md 设计

## 目标

在仓库根目录建立可被 AI 工具自动识别的 `AGENTS.md`，统一后续知识库维护方式，避免技术结论被个人背景限制、重复目录、过时知识和未经验证的完成声明，同时保留服务个人求职所需的真实项目与职业材料。

## 适用范围

规范作用于整个仓库。技术知识章节强调可迁移性；项目深挖和职业章节允许保留真实个人、公司和项目上下文。它不扩展为通用软件项目开发手册，也不重复工具自身已有的基础安全规则。

## 规则结构

1. **知识库定位**：技术原理、算法和工程实践必须通用、可迁移；项目与职业材料可以服务本人求职并保留真实上下文，但要区分事实、待核验信息和通用结论。
2. **内容准确性**：先检查上下文；时效性知识优先核对官方一手资料；明确版本、前提、例外和不确定性。
3. **目录与归档**：保持编号和目录唯一；过时但有参考价值的内容移入 `99-归档`；同步修复导航和相对链接。
4. **代码示例**：示例应可运行，说明复杂度及输入边界；并发、缓存、重试、取消、幂等和安全问题不得被过度简化。
5. **修改方式**：保持最小改动，保留用户已有工作；能从仓库判断的事项直接处理，只有高风险或意图不明确时才询问。
6. **完成验收**：检查格式、链接、代码围栏、空文件、重复目录、地域/个性化残留；核心代码示例执行行为测试。
7. **Git 与交付**：不主动 push，不覆盖用户改动；交付时说明文件、影响范围、验证结果和未完成事项。

## 关键约定

- 指定删除的地域标识在活动区和归档区都不得残留；法律内容可以说明适用法域，但不能伪装成跨法域结论。
- “归档”适用于过时或已被重写取代、且仍有历史参考价值的内容；个人材料不能只因不具备普遍性而归档。
- 项目与职业材料允许出现真实公司、客户、项目和个人贡献，但密钥、账号、内部地址、个人隐私及未公开敏感信息必须删除或脱敏。
- AI 不得仅凭格式检查声称内容正确；关键实现必须执行，时效性事实必须核对。
- 同一编号只能有一个活动目录；新建或改名后必须检查顶层重复项。

## 验收标准

- 根目录存在且仅存在一个标准命名的 `AGENTS.md`。
- 规则使用明确的“必须 / 禁止 / 应当”措辞，避免无法验证的口号。
- 规则覆盖技术通用性、个人求职材料边界、准确性、归档、代码示例、修改流程、验证和 Git 安全。
- 文档通过 Markdown 格式检查和本地链接检查，不包含占位符或相互矛盾的要求。
