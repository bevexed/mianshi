# 面试题库全量审核与算法、设计模式补全方案

## 目标

在不编造个人经历和项目数据的前提下，补齐常见算法题与前端常用设计模式，并对全库 Markdown 内容进行结构、技术、代码和面试表达四个层级的审核与纠正。

## 范围

- 审核仓库内全部 Markdown 文件及其本地链接、目录索引和状态标记。
- 重点补全 `01-JavaScript/手写题/` 下的算法内容。
- 重点补全 `10-架构与设计/` 下的设计模式内容，并消除观察者、发布订阅文章之间的重复和冲突。
- 审核当前工作区已有的未提交改动，但不覆盖或回退与本任务无关的用户改动。
- `【需确认】` 涉及个人经历、真实数据或未提供证据的实现细节时继续保留；只修正有仓库证据支撑的内容。

## 审核分层

### 结构层

- 检查相对链接、图片路径、重命名后的旧路径和目录遗漏。
- 检查模块目录与正文实际状态是否一致。
- 识别重复主题，为重复文章确定唯一正文和兼容入口。

### 技术层

- 核对概念、版本差异、算法复杂度、浏览器行为和框架行为。
- 对可能随版本变化的结论优先采用规范或官方文档，避免无版本限定的绝对表述。
- 区分规范保证、特定实现细节和经验判断。

### 代码层

- 检查示例的语法、返回值、边界条件、时间复杂度和空间复杂度。
- 抽取可独立执行的 JavaScript 示例进行运行验证，重点覆盖空输入、重复值、异常分支和顺序保持。
- 伪代码明确标注为模板或省略实现，避免被误认为可直接运行。

### 面试表达层

- 删除夸张、绝对化或缺少依据的结论。
- 将“定义背诵”调整为“解决的问题、适用条件、代价和项目场景”。
- 个人项目事实没有证据时不推断、不润色成既成事实。

## 算法内容设计

### 通用高频题型

`算法-高频题型.md` 按“识别信号、模板、代表题、复杂度、常见错误”组织，覆盖：

- 哈希、双指针、滑动窗口
- 栈、队列、单调栈、堆
- 链表、二叉树、图的 BFS/DFS
- 排序、二分查找
- 回溯、贪心、动态规划

每一类只保留足以支撑前端面试的典型题，避免扩张为完整 LeetCode 题库。

### 前端专属手写题

`算法-前端专属.md` 聚焦真实业务高频题：LRU、数组和对象扁平化、列表与树转换、大数运算、并发控制、EventEmitter、柯里化、compose/pipe、URL 参数和版本号处理。防抖节流、深拷贝、Promise 等已有独立文章的内容只提供索引，避免重复维护。

## 设计模式内容设计

`常用设计模式.md` 按创建型、结构型、行为型组织，详细覆盖单例、工厂、策略、适配器、代理、装饰器、组合、外观、责任链、状态、命令和迭代器，并补充前端负责人常被问到的依赖注入与控制反转。

每种模式包含：解决的变化、最小示例、前端场景、缺点以及容易混淆的模式。对 React、Vue、NestJS 等框架示例注明它是严格实现、思想应用还是类比，避免把框架 API 机械等同于某个 GoF 模式。

`观察者与发布订阅.md` 作为唯一完整正文；`发布订阅模式.md` 保留为简短兼容入口，防止已有链接失效。

## 验证与完成标准

- 全库本地 Markdown 链接和图片链接无已知断链。
- Markdown 代码围栏成对，目录引用与文件状态一致。
- 新增和修改的可执行 JavaScript 示例通过本地运行验证。
- 算法与设计模式覆盖上述高频范围，且不存在已知复杂度、边界或模式归类错误。
- 无证据的个人事实仍带 `【需确认】`，没有被改写为确定陈述。
- 最终提供涉及文件、影响范围、验证结果和仍需本人确认的事项摘要。
