# NestJS 独立学习模块设计

## 背景

`09-Node与服务端/NestJS核心概念.md` 当前同时包含模块与依赖注入、循环引用、请求生命周期、日志、HTTP 适配器、数据访问和选型边界。文章已经从速查稿增长为多主题文档，继续在单文件中追加会降低学习顺序、定位效率和后续维护性。

本次将 NestJS 从 Node 章节中扩展为独立子目录，保留已有内容，补齐静态模块与动态模块的基础知识，并建立后续系统学习的导航骨架。

## 目标

1. 为 NestJS 建立独立、可持续扩展的学习目录。
2. 将现有单篇文章按职责拆分，不丢失已有内容，不重复维护两份正文。
3. 系统讲清模块、Provider 与依赖注入，重点补充静态模块、动态模块及常用注册约定。
4. 同时服务“系统学习”和“面试复习”，在原理、边界、代码示例和口述答案之间保持平衡。
5. 更新内部导航并验证链接、Markdown 格式和版本边界。

## 非目标

- 本次不一次性写完鉴权、缓存、测试、微服务、WebSocket、部署等全部高级主题。
- 不创建只有标题或占位符的空文章。
- 不把 NestJS 官方 API 手册整段复制到仓库中。
- 不把特定私有项目的业务数据、凭据或未经核实的生产结论带入通用学习文档。
- 不修改与 NestJS 模块无关的已有工作区改动。

## 文件职责

### `目录.md`

- 说明 NestJS 适合解决的问题和学习前置。
- 给出本次已完成的五篇基础文章与建议阅读顺序。
- 按“基础机制 → 工程实践 → 分布式能力 → 生产运行”列出后续学习路线。
- 未完成的高级主题只作路线说明，不链接不存在的文件。

### `01-框架定位与项目结构.md`

- NestJS 的框架定位、应用图和根模块。
- Controller、Provider、Module 的基本协作关系。
- Express/Fastify 适配器的作用与选型边界。
- Node/NestJS 选型与计算密集任务的现有结论。

### `02-模块与依赖注入.md`

- `imports`、`controllers`、`providers`、`exports` 的封装边界。
- 类 Provider、`useValue`、`useClass`、`useFactory`、`useExisting` 和非类 token。
- 默认、请求级和瞬时 Provider 作用域及传播成本。
- 静态模块与动态模块的定义、用途、对比和最小示例。
- `register`、`forRoot`、`forFeature` 及它们的 `Async` 变体的社区约定。
- 动态模块返回的元数据扩展而非覆盖 `@Module()` 静态元数据。
- 共享模块、全局模块、动态模块和懒加载模块的概念分离。
- 循环引用的三种类型、优先拆分责任的方法，以及 `forwardRef`/`ModuleRef` 的边界。

### `03-请求生命周期.md`

- Middleware、Guard、Interceptor、Pipe、Controller 与 Exception Filter 的整体顺序。
- 进入阶段、返回阶段、异常路径和全局/控制器/路由级顺序边界。
- 每种机制应该承担与不应承担的职责。
- 与 AOP、鉴权、校验和统一异常处理文章的交叉链接。

### `04-日志与可观测性.md`

- Nest `LoggerService`、请求上下文和采集链路的三层职责。
- `bufferLogs`/`useLogger` 的启动窗口语义。
- `nestjs-pino` 和 `nest-winston` 的最小配置、能力对比与选型边界。
- request ID、trace context、结构化字段、异常栈、脱敏、采样和保留策略。
- 日志、指标和链路追踪的职责边界。

### `05-数据访问与事务.md`

- 保留现有 TypeORM 中 N+1、批量写入、migration、事务管理器和长事务边界。
- 说明 ORM 只是 NestJS 中的数据访问选项，不把 TypeORM 与框架强绑定。
- 本次不展开为完整的 MySQL 与 ORM 教程，数据库原理继续链接到 `15-数据库`。

## 统一内容模板

每篇基础文章按需使用以下结构，不为了形式强行填充无价值的小节：

1. 核心结论与适用范围。
2. 概念、执行模型或依赖关系。
3. 最小 TypeScript 示例，并标明省略的生产细节。
4. 对比、常见误区和工程边界。
5. 30–40 秒面试回答或高频追问。
6. 复习检查。
7. 当前有效的 NestJS 官方文档或相关一手资料。

## 学习路线

`NestJS/目录.md` 将展示以下渐进路线：

1. **基础机制**：框架定位、模块与 DI、请求生命周期。
2. **工程实践**：配置、校验、异常、日志、数据访问、鉴权、缓存与测试。
3. **后台与分布式能力**：定时任务、队列、WebSocket、微服务与事件。
4. **生产运行**：性能、健康检查、优雅停机、容器化、可观测性与安全。

本次完成五篇基础文章。其他主题只标注学习顺序和与现有章节的关系，不声称已经完成。

## 版本与事实边界

- 框架机制以当前 NestJS 官方文档为主要依据。
- 第三方适配层（例如 `nestjs-pino`、`nest-winston`）以其维护者文档为依据。
- 会受版本影响的执行顺序、日志级别或 API 必须标注边界，不把当前实现表述为永久不变的规则。
- 性能选型使用“特征 + 真实压测”的表述，不编造吞吐量或延迟数字。
