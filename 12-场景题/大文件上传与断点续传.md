# 大文件上传 / 断点续传

> 高频场景题。你的项目里有付款回执上传、附件上传、
> 房型图片、PDF 预览，都能对上。

## 整体方案

```
1. 前端切片（Blob.slice）
2. 计算文件 hash（用于秒传和续传标识）
3. 询问服务端：这个 hash 已经传过哪些片？
4. 只上传缺失的片（并发控制）
5. 全部传完后通知服务端合并
```

---

## 切片

```js
const CHUNK_SIZE = 5 * 1024 * 1024   // 5MB
const chunks = []
for (let i = 0; i < file.size; i += CHUNK_SIZE) {
  chunks.push(file.slice(i, i + CHUNK_SIZE))
}
```

**切片大小怎么定**：
- 太小 → 请求数多，开销大
- 太大 → 单片失败重传成本高，弱网下容易超时
- 常见 1-10MB，可以**按网络状况动态调整**

---

## 计算 hash（秒传的关键）

```js
// 用 spark-md5 增量计算，避免一次读入整个文件
// ⚠️ 大文件会卡主线程，必须放 Web Worker
const worker = new Worker('hash-worker.js')
```

**优化手段**：
- **抽样 hash**——只取首尾片 + 每片中间一小段计算，
  速度快很多，碰撞率在业务场景下可接受
- 大文件必须放 **Web Worker**，否则页面卡死

**秒传**：hash 已存在 → 服务端直接返回成功，不用传。

---

## 并发控制

**不能一次发 100 个请求**——浏览器同域并发有限，
且会挤占其他请求。

```js
async function pool(tasks, limit = 4) {
  const running = new Set()
  for (const task of tasks) {
    const p = task().finally(() => running.delete(p))
    running.add(p)
    if (running.size >= limit) await Promise.race(running)
  }
  await Promise.all(running)
}
```

**这个并发池是常考的手写题**，值得背下来。

## 断点续传

- 上传前先问服务端已有哪些片（`GET /uploaded?hash=xxx`）
- 只传缺失的
- **前端也可以存一份进度**（localStorage/IndexedDB），
  但**以服务端为准**——前端记录可能和实际不一致

---

## 失败重试

```js
async function uploadWithRetry(chunk, retries = 3) {
  for (let i = 0; i < retries; i++) {
    try { return await upload(chunk) }
    catch (e) {
      if (i === retries - 1) throw e
      await sleep(2 ** i * 1000)   // 指数退避
    }
  }
}
```

**要区分可重试和不可重试的错误**——
4xx 参数错误重试多少次都没用。

> 这个思路和你采集服务里的重试策略是一样的，
> 见 [13-项目深挖/住建部企业资质采集服务.md](../13-项目深挖/住建部企业资质采集服务.md)

## 进度显示

```js
xhr.upload.onprogress = e => {
  // 注意：fetch 原生不支持上传进度，需要用 XHR
  // 或者用 ReadableStream（较新，兼容性有限）
}
```

**多片并发时的总进度**：
维护每片的已上传字节数，求和 / 总大小。
**不要按"完成的片数 / 总片数"算**——进度会一跳一跳的。

## 直传 OSS vs 经过自己后端

| | 直传 OSS | 经后端中转 |
|---|---|---|
| 服务端压力 | 小 | 大（流量和带宽都过一遍） |
| 安全 | 需要**后端签发临时凭证/签名** | 后端可控 |
| 复杂度 | 需要处理签名过期 | 简单 |
| 网关限制 | 无 | 受 body size 限制（Nginx 默认 1MB） |

**大文件基本都走直传**。
签名一定要后端生成，**AccessKey 绝不能出现在前端**。

## 其他要点

- **前端先校验类型和大小**——省一次无效上传，
  但**服务端必须再校验一次**（前端校验只是体验）
- **文件类型校验不能只看扩展名**——
  要读文件头（magic number）
- **最大上传数限制**（你简历里提到过统一处理这个）
- 上传中离开页面的提示（`beforeunload`）
