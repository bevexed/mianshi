# 大文件上传与断点续传

可靠上传需要前端、业务服务和对象存储共同定义上传会话、分片校验、并发、重试、合并和清理协议。

## 协议流程

```text
1. 创建上传会话，服务端返回 uploadId、分片规则和临时授权
2. 客户端切片并查询已完成分片
3. 并发上传缺失分片，每片带序号和校验信息
4. 服务端/对象存储校验完整分片集合并完成合并
5. 业务服务验证最终对象，提交元数据并结束会话
```

会话应绑定用户、目标对象、大小、类型和过期时间，防止拿一个 uploadId 覆盖无权访问的对象。

## 分片与并发

```js
function createChunks(file, chunkSize = 8 * 1024 * 1024) {
	const chunks = [];
	for (let start = 0; start < file.size; start += chunkSize) {
		chunks.push(file.slice(start, Math.min(start + chunkSize, file.size)));
	}
	return chunks;
}
```

分片过小会增加请求和元数据开销，过大则提高失败重传成本。默认值必须结合对象存储限制、典型文件、网络和移动端内存实测。并发度也应动态或保守设置，避免占满连接、内存和上行带宽。

```js
async function runPool(tasks, limit = 4) {
	if (!Number.isInteger(limit) || limit < 1) {
		throw new RangeError('limit 必须是正整数');
	}

	const results = new Array(tasks.length);
	let nextIndex = 0;
	let failed = false;

	async function worker() {
		while (!failed) {
			const index = nextIndex++;
			if (index >= tasks.length) return;

			try {
				results[index] = await tasks[index]();
			} catch (error) {
				failed = true;
				throw error;
			}
		}
	}

	const workers = Array.from({ length: Math.min(limit, tasks.length) }, worker);
	await Promise.all(workers);
	return results;
}
```

这版保留结果顺序，并在首个失败后停止领取新任务；已经在途的任务仍需要 `AbortSignal` 才能真正取消。生产实现还要处理取消后的清理、分类重试和进度回收。

## 标识与完整性

- 可靠内容寻址要计算完整文件的密码学 hash，并在服务端验证；大文件计算放到 Worker 中，避免长时间阻塞主线程。
- 抽样 hash 只能作为快速指纹，存在碰撞和漏检，不能单独用于可信秒传或安全校验。
- 如果对象存储支持每分片校验和，应同时校验分片传输完整性。
- “文件已存在”仍要校验当前用户是否有权引用它，避免通过 hash 探测他人文件。

秒传本质上是复用已验证对象，不代表跳过鉴权、病毒扫描和业务绑定。

## 续传、重试与进度

- 续传状态以服务端/对象存储为准，本地 IndexedDB 只保存 uploadId 和辅助进度。
- 只重试超时、连接中断、部分 5xx 等暂时错误；使用上限、指数退避和抖动。
- 401/403 可能需要刷新临时凭证，参数/配额错误不能盲目重试。
- 合并接口应幂等，重复提交同一完整分片清单返回一致结果。
- 总进度按各分片已发送字节之和计算，不按完成片数估算。

XHR 广泛支持上传进度事件。Fetch 上传流在不同浏览器和基础设施中的支持仍需验证，不应只为统一 API 牺牲兼容性。

## 直传对象存储

浏览器直传可以避免业务服务器中转大流量。服务端签发短期、最小权限、限制对象 key/大小/类型的凭证或预签名 URL；长期 AccessKey 绝不能下发到客户端。

中转上传适合需要同步处理、存储不支持直传或合规要求强制流经服务端的场景，但要处理网关 body 限制、磁盘/内存和背压。

## 安全与生命周期

- 客户端类型/大小校验只改善体验，服务端必须重新验证实际内容。
- 不能只信扩展名或浏览器 MIME；按风险做 magic number、解码验证、病毒扫描和内容安全处理。
- 文件名不直接拼接为存储路径，下载时设置安全的 `Content-Type`、`Content-Disposition` 和权限检查。
- 定时清理过期会话和未完成分片，监控失败率、续传率、上传耗时和孤儿存储成本。
