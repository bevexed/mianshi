# 验证码与滥用防护

验证码是提高自动化攻击成本的一种手段，不是身份认证、限流或风控的替代品。是否展示以及采用哪种形式，应基于风险和可访问性权衡。

## 常见方案

| 方案              | 适用                 | 主要问题                                               |
| ----------------- | -------------------- | ------------------------------------------------------ |
| 图片/文字验证码   | 低成本基础挑战       | OCR、可访问性和体验较差                                |
| 滑块/行为挑战     | 风险升级后的交互验证 | 可被自动化模拟，依赖供应商风控                         |
| 短信/邮件一次性码 | 验证用户持有通道     | 费用、轰炸、SIM 劫持、邮箱失陷；不是图形验证码的同义词 |
| 隐形风险评分      | 低摩擦分级           | 误判、隐私、可解释性和供应商依赖                       |

## 服务端设计

1. 挑战由服务端创建，使用高熵随机标识并设置短有效期。
2. 记录必要状态或使用带完整性保护的令牌，绑定用途、会话和风险上下文。
3. 校验必须原子地限制次数并一次性消费，防止并发重复使用。
4. 对账号、IP、设备和全局维度分层限流；避免只按 IP 误伤共享网络。
5. 返回统一错误，防止泄露账号是否存在或挑战的精确内部状态。
6. 记录成功率、攻击绕过率、误伤率和成本，按数据调整触发阈值。

## 短信验证码

- 发送接口和校验接口分别限流；为单号码、设备、IP 和供应商费用设置上限。
- 验证码使用安全随机数，短期有效，限制猜测次数，成功后立即失效。
- 不在日志、分析事件和前端错误中记录明文验证码。
- 登录、改密、提现等高风险操作不能仅依赖短信，应结合现有会话、设备和额外验证。

## 前端职责

- 获取 challenge、渲染供应商组件、提交 token，并处理过期和重试。
- 倒计时只是体验提示，不能作为服务端发送频率控制。
- 提供键盘、读屏或替代验证方式；失败提示不要把用户困在无限挑战中。
- 第三方脚本按非核心依赖隔离，设置 CSP、超时和降级策略。

## 风险分层

优先使用限流、异常检测、蜜罐字段、信誉和行为信号拦截明显滥用；正常低风险用户不展示挑战，可疑请求升级为验证码，高风险操作进一步要求强认证或人工审核。攻击者会适应固定规则，因此需要持续观测而非一次接入后不再维护。
