# 线上白屏排查

处理顺序是先止损和确认影响，再按网络、资源、执行、渲染分层定位，最后补上可观测性与发布防线。

## 1. 止损与影响面

- 刚发布后错误率陡升且影响核心路径：优先暂停发布、关功能开关或回滚。
- 区分全量/灰度、全部页面/单路由、首次访问/客户端跳转、特定浏览器/网络。
- 保存故障版本的构建产物、source map、响应头、配置和错误样本。

回滚也要考虑接口和数据库兼容性，不能假定旧前端一定能调用新后端。

## 2. 分层定位

```text
网络层：HTML 是否到达？DNS/TLS/网关状态如何？
资源层：JS/CSS/chunk 是否 404、被 CSP 拦截或完整性校验失败？
执行层：是否有语法错误、初始化异常或第三方脚本故障？
渲染层：根节点、路由、数据和样式是否让内容不可见？
```

同时检查服务端渲染/水合错误、service worker 缓存和客户端路由 fallback。页面“看起来空”也可能是文字颜色、遮罩层或 CSS 未加载，并非根节点没有子元素。

## 3. 高频原因与预防

### HTML 与不可变资源版本错配

旧 HTML 可能引用已经被删除的旧 hash chunk；新 HTML 也可能在资源尚未全部上传时提前可见。

- hash 静态资源使用长期缓存并按版本保留；不要同名覆盖。
- HTML 使用短缓存或协商缓存，并按“资源先上传、入口后切换”发布。
- 多地域 CDN 验证缓存键和刷新传播，不把“刷新 CDN”当作唯一保证。
- 动态导入失败可以提示刷新，但要限制重载次数，避免死循环。

```js
window.addEventListener('vite:preloadError', (event) => {
	event.preventDefault();

	const key = `chunk-reload:${location.pathname}`;
	if (sessionStorage.getItem(key)) return;
	sessionStorage.setItem(key, '1');
	location.reload();
});
```

### 语法与 API 兼容性

明确浏览器支持范围，用真实目标环境构建和测试。依赖包可能发布未降级语法，polyfill 也只能补 API，不能修复浏览器无法解析的语法。

### 数据或渲染异常

- 在 API 边界验证关键字段，而不只是到处写可选链。
- React 使用 Error Boundary 隔离渲染错误；事件处理器和异步回调仍需单独处理。
- 为路由未匹配、权限不足和关键接口失败提供明确降级页。

### 第三方脚本

异步加载、设置超时和熔断，确保统计/客服等非核心脚本失败不会阻塞启动。第三方脚本仍受 CSP、主线程和全局变量影响，`async`/`defer` 不能解决全部风险。

## 4. 白屏检测

单纯判断根节点是否有子元素容易误报。更可靠的方案组合：

- 框架错误边界和全局未处理错误；
- 对关键页面标记“可交互/核心内容已渲染”；
- 采样 DOM 点位、视口像素或性能时序作为辅助信号；
- 上报版本、路由、资源错误和 trace ID，并严格脱敏。

白屏率、资源加载失败率和核心流程成功率应作为发布观察指标。修复后添加构建产物完整性检查、端到端冒烟和故障演练。
