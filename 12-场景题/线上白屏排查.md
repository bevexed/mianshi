# 线上突然白屏怎么办

> 场景题考的**不是知识，是排查路径**。
> 面试官想看你是「有章法地缩小范围」还是「凭直觉乱猜」。

## 先说框架（比直接猜原因重要）

> 我的顺序是：**先止损，再定位，最后复盘。**
>
> 止损优先——如果是刚发的版本，先回滚，
> 不要在用户还在白屏的时候慢慢查原因。

---

## 第一步：确定影响面

| 问题 | 说明什么 |
|---|---|
| **所有用户还是部分用户？** | 部分 → 灰度/机型/浏览器/网络问题 |
| **所有页面还是某个页面？** | 单页面 → 那个页面的代码或数据 |
| **什么时候开始的？** | 和发版时间对得上 → 八成是发版引起 |
| **能复现吗？** | 不能复现的更麻烦，见 [偶发bug定位.md](偶发bug定位.md) |

**监控在这一步的价值最大**——
Sentry 的错误曲线能直接告诉你什么时候开始、影响多少用户。

---

## 第二步：分层定位

```
1. 网络层：请求发出去了吗？
   → DevTools Network / 用户端抓包
   → HTML 拿到了吗？JS/CSS 拿到了吗？
   → 状态码是什么？403/404/504 各指向不同问题

2. 资源层：JS 加载失败？
   → CDN 挂了 / 发版后旧 html 引用了已删除的新 hash 文件
   → 这是最经典的白屏原因

3. 执行层：JS 报错了吗？
   → Console 有没有错误
   → Sentry 有没有对应的 issue
   → 语法错误（低版本浏览器不支持新语法）会导致整个文件不执行

4. 渲染层：JS 跑了但没渲染出来？
   → 接口返回异常数据导致渲染时抛错
   → 路由匹配失败
   → 根节点没挂上
```

---

## 最常见的几个真实原因

### 1. 发版后 CDN 缓存不一致（最高频）

用户拿到的是**旧的 `index.html`**（CDN 没刷新），
里面引用的是旧 hash 的 JS，而旧文件已经被新版本覆盖/删除 → 404 → 白屏。

**预防**：
- `index.html` 设 `no-cache`
- 发版后刷 CDN
- **旧版本静态资源保留一段时间再删**

> 见 [08-性能优化/缓存与CDN.md](../08-性能优化/缓存与CDN.md)

### 2. 低版本浏览器语法不支持

某个依赖用了新语法没被转译，
低版本 Safari/安卓 webview 直接语法错误。

**预防**：browserslist 配置对，
关键依赖检查是否发布了 ESM+新语法版本。

### 3. 某个接口异常导致渲染时抛错

```js
data.list.map(...)   // data.list 是 null 时整个组件树崩掉
```

**预防**：
- **ErrorBoundary 兜底**——至少不要整页白，展示错误页
- 接口数据做防御性处理
- 关键页面做降级

### 4. 第三方脚本挂了

统计、客服、广告 SDK 阻塞或报错。
**预防**：第三方脚本用 `async`/`defer`，不要阻塞主流程。

---

## 第三步：怎么防止下次再发生

**这一步能拉开差距**——大多数人答完定位就停了。

> 我们的做法是：
> - **ErrorBoundary + 白屏检测**：
>   如果根节点在 N 秒后仍然是空的，上报一条白屏事件
> - **发版后盯监控**——错误率异常立刻回滚
> - **灰度发布**——先放量 5%，没问题再全量
> - 复盘写进文档，同类问题加自动化检查

### 白屏检测怎么做

```js
// 简易版：定时采样根节点
setTimeout(() => {
  const root = document.getElementById('root')
  if (!root || root.children.length === 0) {
    report('white-screen', { url: location.href })
  }
}, 5000)
```

更严谨的做法是**采样页面关键点位的元素**，
判断是否有有效渲染内容。

## 如果面试官追问"那你实际遇到过吗"

【需确认】你的项目里有没有真实的白屏事故？
**有的话一定要讲具体的那一次**——
时间线、怎么发现的、怎么止损的、最后根因是什么。

没有的话诚实说「我们上线前会走灰度，
目前没遇到过大面积白屏，但接了 Sentry 之后
有过几次单页面报错导致局部空白的情况」，
然后讲那个小案例。**别编大事故。**
