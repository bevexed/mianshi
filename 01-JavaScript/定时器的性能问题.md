# 定时器的行为与性能

- `setTimeout(fn, delay)` 的 `delay` 是**最短等待时间**，不是准点保证；
  主线程忙、标签页后台节流和嵌套定时器最小间隔都会让它延后。
- `setInterval` 不会创建并行线程。回调仍在事件循环中串行执行；
  当主线程长期阻塞时，触发时机会延后，不能用它做精确计时。
- 异步回调即使不占用 JS 调用栈，也可能出现“上一轮请求未完成，下一轮又发出”的逻辑重叠。

需要等待上一轮异步任务完成后再安排下一轮时，用递归 `setTimeout`：

```js
async function poll() {
	try {
		await requestStatus();
	} finally {
		setTimeout(poll, 1000);
	}
}
```

动画优先使用 `requestAnimationFrame`；需要后台长期调度的任务应交给服务端或平台调度器。
