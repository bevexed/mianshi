# 调用栈、对象引用与堆内存

> “原始值一定在栈上、对象地址一定在栈上”是常见教学简化，
> 不是 ECMAScript 规范保证。引擎可能装箱、内联对象、寄存器分配或做逃逸分析。
> 面试应把**语言语义**和**引擎实现**分开。

## 调用栈

函数调用通常形成调用帧，后调用的函数先返回：

```js
function first() {
	second();
}
function second() {
	third();
}
function third() {
	throw new Error('x');
}
first();
// 错误 stack 通常能看到 third → second → first
```

递归太深会耗尽调用栈并抛出 `RangeError`。栈深限制取决于引擎、平台和函数形态，
不能背成固定“一万层”；处理不受控深度的数据时用迭代和显式栈。

## 值语义和对象引用

JavaScript 变量保存值。对象值表现为引用语义：复制变量会得到指向同一对象的引用值。

```js
let a = 1;
let b = a;
b = 2;
console.log(a); // 1

const first = { value: 1 };
const second = first;
second.value = 2;
console.log(first.value); // 2
```

这解释了浅拷贝和对象相等性，但无需声称某个“地址”具体放在机器栈的哪个位置。

## 函数参数是按值传递

```js
function update(obj) {
	obj.value = 2; // 修改双方共享的对象
	obj = { value: 3 }; // 只改了局部参数保存的引用值
}

const source = { value: 1 };
update(source);
console.log(source.value); // 2
```

JavaScript 没有能让形参重新绑定外部变量的“按引用传参”。传入对象时，
传递的是对象引用这个值，所以能改属性，但重新给形参赋值不会影响外部变量。

## 堆与垃圾回收

对象等动态数据通常由引擎放在受垃圾回收器管理的内存区域，概念上常称为堆。
对象是否可回收取决于它是否仍从根（全局、活动调用、宿主引用等）可达，
而不是简单的引用计数。

V8 等现代引擎通常使用分代、标记和整理/复制等多种策略；具体代际名称、阈值和算法
会随版本变化。面试重点是：

- 循环引用只要整体不可达也能回收。
- 内存泄漏是“不再需要的对象仍然可达”，例如未清理监听、无限增长的 Map、
  长生命周期闭包或定时器。
- WeakMap 不阻止对象 key 被回收，适合附加元数据，但不等于自动解决所有泄漏。
