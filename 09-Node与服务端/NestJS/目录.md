# NestJS 系统学习 · 目录

NestJS 在 Node.js HTTP 适配器之上提供模块、依赖注入和统一的请求处理机制。这个子目录不只用于背面试题，而是按“先理解应用图，再理解请求边界，最后进入生产工程”的顺序系统学习。

## 学习前置

- 掌握 TypeScript 类、装饰器、泛型，以及接口在编译后会被擦除这一运行时边界。
- 理解 Promise、async/await 和 Node.js 事件循环，能识别阻塞主线程的任务。
- 熟悉 HTTP 方法、状态码、请求头和服务端输入校验的基本概念。

## 建议学习顺序

```text
框架定位
  → 模块与 DI
  → 请求生命周期
  → 日志与故障定位
  → 数据访问与事务
```

其中“模块与依赖注入”这一篇按下面的容器主线展开：

```text
DI Container
  → Provider 与 Injection Token
  → Module 可见性与 Provider 作用域
  → Dynamic Module
  → 生命周期钩子与资源释放
  → 循环依赖
```

这条顺序先回答“对象由谁创建”，再回答“对象如何注册和被看见”，最后处理配置、销毁与依赖图异常；不要从 `forwardRef()` 或 `forRootAsync()` 这些 API 名称倒着背框架。

阅读每篇时至少完成三件事：

1. 合上文档，用 30–40 秒说清核心概念和边界。
2. 独立写出最小示例，不只记装饰器名称。
3. 用一个反例解释“什么情况不应该这样做”。

## 后续扩展路线

以下内容是后续学习路线，尚未在本目录中写成独立文章：

1. **工程实践**：配置管理、输入校验、异常映射、鉴权与授权、缓存和测试。

3. **分布式能力**：微服务 transport、消息交付语义、链路追踪与配置一致性。
4. **生产运行**：性能压测、健康检查、优雅停机、容器化、安全基线与故障恢复。

## 版本边界

NestJS 的执行顺序、适配器能力和第三方模块都可能随版本变化。文章以当前官方文档为基线；实际项目中还要核对已安装版本、适配器和插件的类型定义与发布说明。
