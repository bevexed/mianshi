# SSRF、文件上传与路径安全

这几类漏洞都让不可信输入影响服务端能够访问的网络或文件系统。由于服务端通常拥有内网、云元数据、对象存储和本地文件权限，攻击影响会显著高于普通浏览器请求。

## SSRF

SSRF 发生在应用根据攻击者可控信息发起服务端请求，例如 URL 预览、头像抓取、Webhook、PDF/截图、仓库导入和代理接口。目标不只限于 HTTP，也可能涉及 `file:`、FTP、Gopher 等客户端支持的 scheme。

### 防护分层

1. **减少能力**：业务只需要固定目标时，不接收完整 URL；让客户端提交资源 ID，由服务端映射目标。
2. **允许列表**：限制 scheme、主机、端口和路径；通常只允许 HTTPS 与明确服务。
3. **统一解析**：使用成熟 URL 解析器，拒绝凭据、歧义主机、非常规 IP 表示和不需要的协议。
4. **解析后检查**：解析全部 A/AAAA；除明确允许的受信内部目标外，要求候选 IPv4/IPv6 都不是 loopback、私网、链路本地、保留地址或云元数据地址。
5. **重定向策略**：默认关闭自动重定向；确需跟随时，对每一跳重新解析和校验并限制跳数。
6. **防 DNS 重绑定**：让实际连接使用已校验地址，或由强制出站代理完成解析和策略执行；不能校验后再触发一次不受控 DNS 解析。连接时仍要正确处理 HTTP `Host`、TLS SNI 和证书校验，并限制 DNS 与网络出口。
7. **网络隔离**：用 egress proxy、防火墙和服务身份只开放必要出站目标，阻断应用直达控制面和元数据服务。
8. **资源约束**：限制超时、响应大小、内容类型、并发和下载次数，不把返回内容原样反射给用户。

黑名单很难完整覆盖 IPv6、编码、DNS、重定向和新协议，应作为无法使用允许列表时的补充，而不是唯一边界。

## 文件上传

上传风险包括可执行文件、解析器漏洞、XSS 内容、恶意文档、覆盖文件、路径穿越、压缩炸弹、存储耗尽和未授权读取。

| 环节       | 防护                                                         |
| ---------- | ------------------------------------------------------------ |
| 接收       | 认证授权、CSRF 防护、单文件/总量/频率上限、超时             |
| 类型判断   | 扩展名允许列表 + MIME + 文件签名；不信任客户端 `Content-Type` |
| 文件名     | 服务端生成随机 ID，原始名只作转义后的展示元数据             |
| 处理       | 低权限隔离进程，限制 CPU/内存/时间；按风险使用杀毒/CDR       |
| 存储       | 优先独立主机/私有对象存储，至少放在 webroot 外并禁止执行     |
| 下载       | 重新做对象授权，设置安全类型/下载响应头，避免内联活动内容    |

- 图片不能只看扩展名；解码后重新编码可移除部分多余内容，但解析库本身仍需更新和隔离。
- ZIP/文档处理要限制展开后的文件数、总大小、递归深度和压缩比，防止资源耗尽。
- 上传成功与“扫描完成可使用”应是两个状态，异步扫描失败时不能默认放行。
- 公共下载应使用不可执行域名、正确 `Content-Type` 和 `X-Content-Type-Options: nosniff`；私有文件使用短期授权，不等同于只靠难猜 URL。

大文件协议与恢复流程见 [大文件上传与断点续传](../12-场景题/大文件上传与断点续传.md)。

## 路径穿越与归档解压

```text
危险：baseDir + userInput
推荐：客户端提交业务 ID → 服务端查元数据 → 映射到服务端生成的存储 key
```

如果业务必须处理路径：

1. 只允许有限文件名/扩展名，不接受绝对路径、分隔符和父目录片段；
2. 规范化后解析为绝对路径，确认结果位于预期基目录内；
3. 考虑 URL/Unicode 双重编码、大小写、Windows 驱动器/UNC 和不同分隔符；
4. 防范符号链接和检查后替换造成 TOCTOU，优先使用安全文件描述符 API 和隔离目录；
5. 解压每个归档条目前校验目标路径，拒绝 Zip Slip、符号链接和超额资源；
6. 运行账号只拥有指定目录权限，不能读取应用密钥、源码或系统文件。

## XXE、开放重定向与相邻风险

- 不需要 XML 外部实体时在解析器中关闭 DTD、外部实体和外部网络访问；优先使用安全默认配置或简单数据格式。
- 跳转地址使用服务端路由名/允许列表，不把任意 URL 直接交给 `Location`；否则可被用于钓鱼、OAuth token 泄露或安全校验绕过。
- URL 导入、远程图片、文档转换和压缩包解析都应同时评审 SSRF、文件类型、路径和资源耗尽，不能按功能割裂。

## 验证清单

- 测试 IPv4/IPv6、域名、多次解析、重定向、不同协议和超大/慢响应。
- 验证容器/主机的实际出站策略，应用层拦截失效后仍不能访问敏感网络。
- 上传测试覆盖伪装扩展名、错误 MIME、活动内容、超大图片、归档和同名并发。
- 检查上传后的查看、下载、分享、删除和扫描回调是否都执行对象授权。
- 路径测试覆盖编码、跨平台分隔符、符号链接、归档条目和竞争条件。
