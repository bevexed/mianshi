# Web 安全基础与威胁建模

Web 安全不是“过滤特殊字符”，而是在身份、权限、数据和执行环境之间建立可验证的信任边界。浏览器默认安全机制只能限制一部分跨源行为，服务端仍要独立完成认证、授权、输入处理和审计。

## 先明确保护什么

| 目标       | 典型失败                                           |
| ---------- | -------------------------------------------------- |
| 机密性     | 越权读数据、日志泄密、密钥进入前端包或代码仓库     |
| 完整性     | 参数篡改、供应链污染、伪造请求、未授权状态变更     |
| 可用性     | 资源耗尽、上传炸弹、正则回溯、无界队列和依赖故障   |
| 身份真实性 | 撞库、会话劫持、弱重置流程、令牌验签或受众校验错误 |
| 可追责性   | 关键操作无审计、日志可被注入、时间线和主体无法关联 |

安全风险还必须结合业务影响：同一个公开内容站和保存敏感资料的系统，资产价值、攻击者动机和处置优先级完全不同。

## OWASP Top 10:2025 映射

| 类别                                        | 在本章中的落点                         |
| ------------------------------------------- | -------------------------------------- |
| A01 Broken Access Control                   | 对象/功能/租户授权、CSRF、SSRF         |
| A02 Security Misconfiguration               | 安全头、CORS、默认账号、错误与部署配置 |
| A03 Software Supply Chain Failures          | 依赖、构建、制品、发布和 SBOM          |
| A04 Cryptographic Failures                  | 传输、存储、密钥和敏感数据生命周期     |
| A05 Injection                               | XSS、SQL/NoSQL、命令和模板注入         |
| A06 Insecure Design                         | 威胁建模、业务不变量和滥用场景         |
| A07 Authentication Failures                 | 登录、恢复、MFA、会话和令牌            |
| A08 Software or Data Integrity Failures     | 更新、反序列化、第三方脚本与数据完整性 |
| A09 Security Logging and Alerting Failures  | 安全事件、关联、告警和保留             |
| A10 Mishandling of Exceptional Conditions   | 失败关闭、资源上限、回滚和异常状态     |

Top 10 的类别会随版本调整；不要把排名当成某个项目的风险优先级，也不要因为漏洞不在 Top 10 就忽略它。

## 威胁建模的最小流程

### 1. 画数据流与信任边界

```text
用户/第三方页面
  → CDN/WAF/反向代理
  → Web/API 服务
  → 数据库、缓存、消息队列
  → 对象存储、第三方 API、内部服务
  → CI/CD、制品和运行环境
```

标出每条边的协议、身份、权限、数据敏感度和失败行为。代理、队列、定时任务、Webhook、文件处理器和后台管理端经常被漏掉。

### 2. 枚举滥用场景

- 未登录、普通用户、管理员、内部服务和被攻陷依赖分别能做什么？
- 能否改 ID、租户、价格、角色、回调 URL 或状态字段获得额外能力？
- 重放、并发、乱序、超时、部分失败时，业务不变量是否仍成立？
- 攻击者能否让系统读取内网、解析恶意文件、执行不可信模板或耗尽资源？
- 日志、错误、前端包、Source Map、备份和监控事件是否泄露同一份敏感数据？

### 3. 把控制放在正确边界

| 控制             | 正确位置                                                   |
| ---------------- | ---------------------------------------------------------- |
| 认证             | 可信服务端验证身份凭据；前端路由守卫只负责体验             |
| 授权             | 每次访问资源时按当前主体、动作、资源和环境判断              |
| 输入校验         | 接收边界按业务类型和允许值拒绝非法数据                      |
| 输出编码/参数化  | 数据进入 HTML、SQL、命令、模板等解释器之前按上下文处理      |
| 限流与资源上限   | 网关和业务层共同实施，并按账号、设备、租户、IP 等多维治理   |
| 审计             | 记录服务端确认的主体、结果和资源，不信任客户端自报关键字段   |

## 通用设计原则

1. **默认拒绝、失败关闭**：未知权限、验签失败、依赖超时或策略不可用时，不自动放行敏感操作。
2. **最小权限**：用户、服务账号、数据库连接、CI token 和云角色只拿完成任务所需权限。
3. **服务端不信任客户端**：隐藏按钮、前端校验、不可枚举 ID 和 TypeScript 类型都不是安全边界。
4. **控制集中且靠近敏感操作**：统一中间件减少遗漏，但对象级授权仍要理解业务资源。
5. **允许列表优先**：状态、协议、主机、文件类型、跳转目标和动态标识符应从有限集合选择。
6. **纵深防御**：根因修复之外叠加 CSP、网络隔离、速率限制、WAF、审计和告警，避免单点失守。
7. **安全默认值可演进**：先用报告模式和观测确认影响，再收紧策略；例外必须有所有者和过期时间。

## 评审与验证

- 需求评审：写出资产、滥用故事、权限矩阵、数据保留和失败策略。
- 设计评审：核对每个信任边界的身份、授权、校验、加密和审计。
- 代码评审：搜索危险 sink、宽泛 CORS、硬编码密钥、缺少授权和错误直出。
- 自动化：单元/集成测试负向权限，SAST、SCA、秘密扫描和 IaC 检查分层门禁。
- 运行时：监控登录失败、权限拒绝、策略绕过、异常出站请求和高风险配置变化。
