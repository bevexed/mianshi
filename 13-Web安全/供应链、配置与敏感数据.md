# 供应链、配置与敏感数据

现代 Web 应用不仅信任源码，还信任包管理器、依赖维护者、构建脚本、CI runner、基础镜像、制品仓库、部署配置和第三方脚本。供应链安全要保护“从提交到生产”的完整路径，而不只是定期跑一次依赖扫描。

## 供应链攻击面

```text
源码与开发账号
  → 依赖解析、registry、安装脚本
  → CI runner、构建密钥、基础镜像
  → 制品、签名、发布通道
  → CDN/运行环境、第三方脚本和更新机制
```

任一环节被篡改，都可能在合法构建或发布身份下进入生产。

## 依赖与构建防护

1. 提交并严格使用 lockfile，CI 使用冻结安装，避免构建时悄悄解析到不同版本。
2. 配置可信 registry 和包 scope，防 dependency confusion、拼写相似包和错误源回退。
3. 新依赖评估必要性、维护状态、权限、体积、安装脚本和传递依赖；能用平台 API 时减少依赖。
4. SCA/漏洞扫描覆盖直接和传递依赖、容器与运行镜像，但结合可达性、暴露面和业务影响定优先级。
5. 更新分小批、经测试和 review 合并；高风险维护者/所有权变化、废弃包和异常发布单独告警。
6. CI 使用短期身份和最小权限，外部 PR 不接触发布密钥；保护分支、环境和人工审批边界。
7. 构建一次、逐环境晋级同一不可变制品；生成 SBOM，并在条件允许时记录来源证明/签名和校验。
8. runner、缓存和制品库隔离，防一个项目读取另一个项目的 token、缓存或产物。

漏洞扫描不是完整性证明：没有已知 CVE 的恶意更新、被盗发布账号和构建脚本篡改仍可能绕过。

## 密钥管理

- 浏览器包、移动端资源和公开仓库中的值都应视为可读取；真正的服务端密钥不能下发前端。
- 使用密钥管理系统或工作负载身份，优先短期凭据；按服务、环境、用途分离权限。
- 不在源码、镜像层、CI 日志、错误、聊天记录和客户端分析事件中保存密钥。
- 建立发现、撤销、轮换、再部署和影响追踪流程。密钥泄露时先撤销/限制，而不是只删除 Git 记录。
- webhook/API 签名验证包含算法、时间窗口、主体和重放防护；轮换期明确双 key 行为。

## 敏感数据与密码学

1. 先减少收集、缩短保留、限制复制和导出；不存在的数据无法被泄露。
2. 传输使用正确验证证书的 TLS，内部服务也不因“在内网”跳过身份验证。
3. 静态加密使用成熟平台和算法，密钥与密文分离并控制解密权限；不要自创密码协议。
4. 密码使用专用密码哈希，而不是可逆加密；可恢复秘密使用受管密钥和认证加密。
5. 日志、追踪、指标、缓存、搜索索引、备份和测试数据都纳入同一数据分类与保留策略。
6. 删除要覆盖主存储及既定的缓存、索引和备份生命周期，并记录法规/审计例外。

## 安全配置

| 风险               | 防护                                                         |
| ------------------ | ------------------------------------------------------------ |
| Debug/错误详情     | 生产关闭调试；对外稳定错误码，对内用 trace ID 关联脱敏日志   |
| 默认账号/样例服务  | 部署前移除或禁用，启动时检查危险默认值                       |
| 开放管理面         | 独立网络/身份/MFA/审计，最小暴露，不只靠隐藏路径             |
| 宽泛 CORS/安全头   | 策略即代码、环境一致、自动测试实际响应                       |
| 云/IaC 权限        | 最小 IAM、加密、网络边界、漂移检测和变更审批                 |
| 目录/存储桶公开    | 默认私有、显式分享、持续检测公开策略和对象 ACL               |
| 不安全异常处理     | 未知状态失败关闭；限制重试、递归、队列、内存、时间和响应大小 |

配置例外必须写明所有者、原因、补偿控制和到期时间。只在生产手工修补会导致测试环境与部署模板继续复制风险。

## 完整性与异常条件

- 不执行未经验证的更新、插件、模板或反序列化数据；签名验证失败必须停止处理。
- 支付、库存、权限等状态转换使用服务端不变量、幂等和并发控制，不依赖请求顺序“通常正确”。
- 超时、部分失败、重试耗尽和依赖返回畸形数据时，不能跳过授权、验签或校验进入成功分支。
- 限制解析深度、集合大小、正则复杂度、上传/解压和异步积压，防异常输入演变成可用性攻击。
- 失败响应不泄露堆栈和内部拓扑，但审计中要能区分策略拒绝、输入错误和系统故障。

## 验证清单

- 从开发机到生产列出每个身份、密钥、网络出口、缓存和制品写权限。
- 验证 lockfile 冻结、registry、外部 PR 权限、发布审批和不可变制品。
- 运行依赖/容器/IaC/秘密扫描，并测试误报处理不会形成永久白名单。
- 从构建产物、Source Map、镜像历史、日志和监控事件反查敏感数据。
- 演练依赖投毒、密钥泄露、制品撤回和紧急轮换，记录恢复时间与缺失证据。
