# 图像加载优化

字不如表，表不如图。图像资源的使用占比也因此越来越大。

如果网站中使用的图片资源未进行恰当的优化，势必会带来诸多问题，如

1. 巨量的访问请求引发传输带宽的挑战
2. 大尺寸图片需要过久的等待时间



## 图像优化
图像优化的方向主要是

1. 图像的选取和使用
2. 图像的加载和显示

### 图像基础
图像资源优化的根本思想是压缩

#### 图像是否有可替代性
1. 使用 css3 的滤镜等功能处理图片，达到适应不同场景的需求
2. 图像上的文字通过前端代码进行添加

#### 矢量图和位图
##### 矢量图
1. 任何比例缩放下呈现出同样清晰的展示效果
2. 适用于形状简单的几何图形
3. 对细节展示不够丰富
4. 使用时可删除非必要信息达到压缩的目的

##### 位图
1. 可以提供丰富的细节
2. 放大或缩小都可能会失真
3. 体积较大

#### 分辨率
1. 图像分辨率
2. 设备分辨率
3. 使用  img 标签的`srcset`针对不同的设备提供不同分辨率的图片
4. 使用 `picture`标签适配

#### 压缩的有损和无损
图片需要先经过适当的有损压缩，通过降低源文件质量的方式降低图像文件大小，在通过无损压缩尽可能的降低图片的大小

1. 无损压缩是必要的环节
2. 有损压缩根据实际情况选择

### 图像格式
不同格式的图片有不同的使用场景

#### JPEG
1. 有损压缩算法
    1. 通过去除相关冗余图像和色彩数据等方式获得较高的压缩率
    2. 基线模式：从上往下逐渐加载
    3. 渐进式：从低质量模糊图片逐渐变成高质量清晰图片
        1. 优点：用户感知性高
        2. 缺点：解码速度相对基线模式慢
2. 可以展示出相当丰富的图像内容
3. 不支持透明度
4. 常做 背景图、轮播图、商品bannner图
5. 不适用logo、图标等需要较强线条感和强烈色对比的场景

#### GIF
1. 只用于展示动画
2. 不适用展示照片
3. 优化：通过抽离多余动态帧的方式来达到压缩的目的
4. git较大时使用视频代替

#### PNG
1. 无损压缩的高保真图片格式
2. 支持透明度
3. 文件尺寸较大
4. 优化：删除多余的信息快进行压缩

#### WebP
1. 有较高的视觉体验
2. 较小的文件尺寸
3. 支持率不高
    1. 通过`source`标签来兼容
    2. 后端通过`accept`字段判断返回对应图片

#### SVG
参考[矢量图](#m006d)

#### Base64
1. 只是一种编码格式
2. 只有图片巨小的时候才考虑使用

### 使用建议
#### CSS Sprite（雪碧图）
将多张小图标拼接成一张大图，从而有效减少http请求已达到加速显示内容的技术

使用需求：

1. 不会随用户信息变化而变化的静态资源
2. 所拼接的单张图片尽量要小

> http2可以在一个http连接上发起多次请求，所以建议加载多张图像文件
>

#### Web字体
矢量图标的集合，具有矢量图标所有的特点

1. 存在兼容问题
2. 使用时注意排序
3. 通过**子集内嵌**的方式按需加载字体
4. 可以使用`<link rel="preload as='font'>` 的方式实现文字的预加载

#### display:none 的使用
```html
<div style="display:none">
  <!-- 图片会被加载 -->
  <img src='img'/>
</div>


<div style="display:none">
  <-- 图片不会被加载 -->
  <div style='background:url(img)'/>
</div>
```
