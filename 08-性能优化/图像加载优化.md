# 图像加载优化

## 核心目标

1. 不传输用户当前设备不需要的像素。
2. 用合适格式与质量降低字节数。
3. 让 LCP 图像尽早被发现和高优先级加载，延后非首屏图像。
4. 预留尺寸避免 CLS，提供有意义的替代文本。

## 格式选择

| 场景                     | 建议起点                                                              |
| ------------------------ | --------------------------------------------------------------------- |
| 照片、复杂图像           | AVIF/WebP，按画质和编解码成本对比；需要时回退 JPEG                    |
| 需要透明的位图           | AVIF/WebP/PNG，用实际图像比较                                         |
| 图标、logo、几何图形     | 优先 SVG，但外部不可信 SVG 要做安全处理                               |
| 动画                     | 优先评估 MP4/WebM/AV1 等视频；简短小动画再比较 animated WebP/AVIF/GIF |
| 截图、锐利线条与无损需求 | PNG 或无损 WebP/AVIF，按产物验证                                      |

“AVIF 一定最小”或“WebP 一定比 JPEG 好”都不是通用结论。
要用目标质量、图像类型、编码耗时、解码成本和兼容范围比较。

## 响应式图像

```html
<picture>
	<source type="image/avif" srcset="hero-640.avif 640w, hero-1280.avif 1280w" />
	<source type="image/webp" srcset="hero-640.webp 640w, hero-1280.webp 1280w" />
	<img
		src="hero-1280.jpg"
		srcset="hero-640.jpg 640w, hero-1280.jpg 1280w"
		sizes="(max-width: 720px) 100vw, 1200px"
		width="1200"
		height="675"
		fetchpriority="high"
		alt="产品界面概览"
	/>
</picture>
```

- `srcset` 提供候选资源，`sizes` 告诉浏览器图像在当前布局中的预期显示宽度。
- `picture` 适合格式协商或艺术方向（不同屏幕使用不同裁剪）。
- `width`/`height` 用于推导宽高比，CSS 仍可用 `width: 100%; height: auto`
  调整响应式尺寸。

## 加载策略

- **LCP 候选图像**：不用 `loading="lazy"`，尽量直接出现在 HTML 中，
  必要时使用 `fetchpriority="high"` 或对背景图像 preload。不要给多张图都设高优先级。
- **非首屏图像**：原生 lazy loading + 尺寸占位；高度自定义触发再用 Intersection Observer。
- **列表图像**：由图像 CDN 按宽度、DPR、格式和质量生成变体，
  对参数做白名单与上限，防止无界变体穿透缓存。
- **失败处理**：提供稳定占位和重试/降级，避免 `onerror` 回退 URL 再次失败时无限循环。

## Base64、Sprite 和图标字体

- Base64 会增加文本体积、不能独立缓存，只对极小且与父资源同生命周期的资产评估。
- CSS Sprite 在 HTTP/1 时代用于减请求，现在会带来缓存粒度、维护和无用像素成本，
  通常优先 SVG sprite 或独立资源。
- 图标字体可能出现无障碍、字体加载闪烁和整包下载问题，
  现代项目通常优先 SVG 图标；使用字体时要做子集化和正确的文本替代。
