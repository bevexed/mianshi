# 前端页面的生命周期

## 从导航到可交互

```text
导航触发
  → 缓存/Service Worker 决策
  → DNS → 建立或复用 TCP/QUIC + TLS 连接
  → 发送请求 → 服务端/CDN 响应（TTFB）
  → 流式接收 HTML，主解析器 + preload scanner 发现资源
  → CSSOM/DOM，脚本下载与执行
  → style → layout → paint → composite
  → FCP/LCP，框架水合或客户端挂载
  → 后续交互（INP）与布局稳定（CLS）
```

不是每次导航都会经历全新 DNS/TCP/TLS。浏览器可能命中缓存、
复用连接、使用 HTTP/2/3 多路复用，或由 Service Worker 响应。

## DOM 事件的语义

| 事件               | 表示                                 | 不表示                         |
| ------------------ | ------------------------------------ | ------------------------------ |
| `DOMContentLoaded` | HTML 已解析，defer/module 脚本已执行 | 图片、字体和所有异步数据已完成 |
| `load`             | 文档与主要依赖资源已加载             | 页面性能良好或业务已可用       |
| `pageshow`         | 页面显示，包括从 bfcache 恢复        | 每次都是新页面实例             |
| `pagehide`         | 页面即将隐藏/离开，对 bfcache 更友好 | 页面一定被销毁                 |
| `visibilitychange` | 文档可见性变化                       | 可作为可靠的“卸载完成”事件     |

`beforeunload`/`unload` 不适合作为通用数据上报和清理机制：
它们可能不触发，并会影响或阻碍 bfcache。
未保存表单需要阻止离开时，只在确实有未保存变更期间动态注册 `beforeunload`。

## bfcache 恢复

浏览器后退/前进时可以保留完整页面快照，恢复时不走完整重新加载。

```js
window.addEventListener('pageshow', (event) => {
	if (event.persisted) {
		// 检查过期的身份/数据并按需重新验证
	}
});
```

从 bfcache 恢复后，网络连接可能已断、数据可能陈旧、计时器可能需要重新校准。
应在 `pageshow`/visibility 边界按需恢复，不要假设组件一定重新挂载。

## 与性能的对应

- **TTFB 慢**：看 CDN/缓存、连接、服务端排队、查询与流式响应。
- **LCP 慢**：拆资源发现、下载、优先级与渲染延迟。
- **INP 差**：看输入延迟、处理时间和呈现延迟，定位长任务与布局抖动。
- **CLS 差**：找未占位媒体、字体、异步插入与动画造成的意外位移。
