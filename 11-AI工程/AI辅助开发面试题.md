# AI 辅助开发面试题：12 条追问链

> 使用方式：先只说每题的 30 秒短答；面试官继续追问时，再展开“追问点”。下文的项目证据只来自实际使用 Codex、Claude Code 的协作经历。

## Q1：AI 辅助开发对你最大的使用价值是什么？

**30 秒短答**

- **结论：**AI 最大的价值是缩短代码定位、调用链理解和候选方案形成时间，不是替我交付功能。
- **证据：**进入既有 Spring Boot 多模块工程时，我先让 Codex、Claude Code 梳理 README、相似模块和菜单权限链路，再小步实现。
- **边界：**我没做严格前后统计，不报效率数字；需求、风险和验收仍由我负责。

**追问点：**继续说明“先读规则、再列不变量、分层验证”的个人闭环，以及陌生工程里哪些信息必须回到源码确认。

## Q2：怎么证明你真正理解 AI 生成的代码？

**30 秒短答**

- **结论：**我的标准是能讲清请求到落库的字段和调用路径，不能解释的改动不提交。
- **证据：**菜单新增允许自定义 ID 时，我从请求模型追到 Convert、Service 和落库，发现 Convert 漏掉 ID，最后会错误走自动编号。
- **边界：**相似模块只能提供候选模式，不能替代当前业务规则；权限、事务和历史数据语义要由我逐项确认。

**追问点：**可把链路展开为请求模型 → Convert → Service → 数据访问，并解释为什么仅看 Controller 或编译结果不够。

## Q3：上下文过长或 AI 幻觉时，你怎么处理？

**30 秒短答**

- **结论：**我只给当前切片需要的源码、规范和脱敏失败输出，并要求区分事实、假设和待验证项。
- **证据：**补分类路径时，工具定位 Service 和 Convert；我用两层测试分别验证路径和字段传递。
- **边界：**工具找不到源码或需求依据时，我会标记“需要确认”，不会让它按常见做法补齐权限、租户或迁移规则。

**追问点：**说明长任务只保留目标、不变量、当前文件和真实验证输出；切换切片时重新读取相关源码，不依赖对话记忆。

## Q4：数据安全怎么保证？

**30 秒短答**

- **结论：**我只给任务需要的代码和脱敏错误，生产数据、密钥和客户日志不进上下文。
- **证据：**我只向工具提供任务所需代码和脱敏信息；生产库、生产 SQL、部署和发布都不授权给它。
- **边界：**`.gitignore` 只防误提交；账号类型和模型数据保留政策仍须按公司制度核实。

**追问点：**可举脱敏方式：保留字段关系和错误特征，把真实 Token、手机号、租户标识替换为占位值；高风险操作仍需人工确认。

**不要这样说：**“我会上传全部仓库和生产日志，让 AI 一次分析完。”

## Q5：AI 生成的测试可靠吗？

**30 秒短答**

- **结论：**AI 只生成测试草案；场景要先由需求和历史缺陷定义，还要确认错误实现会让测试失败。
- **证据：**分类路径用 JUnit 5 分测 Service 路径和真实 Convert 字段，避免 Mock 隐藏丢字段。
- **边界：**Mockito 单测不能替代编译、真实 SQL、鉴权和接口联调。

**追问点：**说明我优先断言返回结果、业务异常和必要协作，而不是把私有方法调用次数等实现细节写死。

**不要这样说：**“测试通过就一定安全。”

## Q6：AI 的首次实现出现过什么真实错误？

**30 秒短答**

- **结论：**首次候选实现会遗漏跨层约束，编译通过也不能说明业务字段真的保留下来。
- **证据：**菜单自定义 ID 的输入已经允许，但 Convert 漏映射该字段，后续逻辑就走了自动生成；我补齐转换，并用真实 Convert 写回归测试。
- **边界：**这证明的是这个字段链路曾有缺陷，不代表所有菜单场景都已穷尽；新增数据迁移或历史数据处理仍要单独评审。

**追问点：**如被追问第二个案例，可说明逻辑删除记录普通查询看不到但仍占主键，因此自动编号和自定义 ID 都要按包含删除记录的口径检查。

**不要这样说：**“AI 能完全自动完成首次实现，人工不必逐层检查。”

## Q7：你如何评估使用 AI 后的收益？

**30 秒短答**

- **结论：**我看可评审变更周期、返工和缺陷逃逸，不看生成代码行数。
- **证据：**菜单自定义 ID 改造中，它协助追踪请求、Convert 和 Service 链路；我确认漏映射、完成修正并用回归测试固化。
- **边界：**没有严格同类任务对照就不报数字；速度增加返工或缺陷不算收益。

**追问点：**后续可按同类任务持续记录交付周期、评审返工次数、关键行为测试数和人工接管率，再同时观察质量趋势。

**不要这样说：**“用了 AI 后固定提升百分之五十，且实现零缺陷。”

## Q8：哪些任务你不会直接委托给 AI？

**30 秒短答**

- **结论：**生产迁移、支付鉴权、跨租户、密钥和不可回滚核心链路，我不让 AI 自主执行或决策。
- **证据：**菜单权限有历史数据和缓存，我先确认不改表、不清数据，再审查权限、事务和删除约束。
- **边界：**高风险任务可让 AI 辅助分析，但要缩小权限、补足证据和回滚方案，关键决定由人做。

**追问点：**可按低、中、高风险说明自主程度：低风险可给局部初稿，中风险先有方案和测试清单，高风险以分析和专项验证为主。

## Q9：你实际怎么使用 Codex 和 Claude Code？

**30 秒短答**

- **结论：**我实际只用 Codex、Claude Code，并按同一协作流程使用。
- **证据：**它们协助检索规则和调用链、生成局部草案；我审 diff、运行目标测试和相关模块编译。
- **边界：**工具不能替代业务判断，未核实的模型能力、数据政策或自动化程度不能当作实践事实。

**追问点：**可进一步讲任务输入包含目标、范围、现有模式、不变量、风险、验证和输出要求；假设必须显式标注。

## Q10：Cursor、Copilot 等工具你用过吗？

**30 秒短答**

- **结论：**我可以从行业认知解释它们常见的补全或代理式协作定位，但实际可举证的使用经验只有 Codex、Claude Code。
- **证据：**我能举证的是用 Codex、Claude Code 协作追踪菜单 ID 转换缺陷；其他工具没有对应项目证据。
- **边界：**没有亲自使用和复盘的工具，我不会假装熟练，更不会把行业资料当作个人项目成果。

**追问点：**如被要求比较，先说明比较维度是上下文获取、权限控制、diff 审查和验证闭环；没有实操证据的结论只限于行业认知。

**不要这样说：**“Cursor、Copilot 没用过也可以假装熟练。”

## Q11：AI 写的代码出问题，责任和回滚怎么处理？

**30 秒短答**

- **结论：**提交、评审和发布代码的人负责；协作工具只给候选方案。
- **证据：**发现逻辑删除记录仍占用主键后，我确认数据库约束，修正编号查询和自定义 ID 检查，并加回归测试。
- **边界：**回归只覆盖已知问题，合并、发布和回滚仍由人根据证据决定。

**追问点：**说明回滚准备从小 diff 开始：保留可审查变更、验证输出和影响范围，必要时按既有发布流程执行人工回滚，而不让工具自行发布。

**不要这样说：**“代码责任归 AI，提交者无需承担后果。”

## Q12：团队怎样把 AI 协作工程化？

**30 秒短答**

- **结论：**把仓库规则、权限边界和质量门槛放进流程，工具代码与人工代码同标准审查验证。
- **证据：**我构建的 ng-design-mcp 是 UI 规范上下文服务，不是第三款编码助手；它用 `evals/queries.json` 验证检索。
- **边界：**MCP 不能保证模型调用；指标、索引和公司治理制度未核实前不能当作已落地事实。

**追问点：**可从个人辅助、仓库上下文、流程集成和平台治理四层展开：代码所有权、最小权限、PR 审查、测试与编译证据，以及模型和数据策略。

## 口述训练方式

1. **第一轮：只答 30 秒结论。**按“结论—证据—边界”顺序说完整，控制在正常语速约 30 秒，不展开技术细节。
2. **第二轮：补一条项目证据。**每题只补最匹配的案例：Convert 丢 ID、逻辑删除主键、分类路径双层验证或 ng-design-mcp，不重复整段项目背景。
3. **第三轮：接受连续追问。**让同伴围绕追问点连续发问，练习把工具能力、验证证据和诚实边界连成闭环。

卡住时只回看本题的关键词，不逐字背稿；目标是能根据问题选择事实、说清证据，也能主动说明尚待确认的边界。
