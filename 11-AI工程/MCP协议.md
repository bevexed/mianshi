# MCP（Model Context Protocol）

MCP 是连接 AI 应用与外部系统的开放标准。它定义了能力发现、消息交换和若干通用原语，使支持同一协议的客户端与服务端可以减少定制适配；它不保证任意客户端都实现所有能力，也不意味着一次实现可以在所有宿主中无差别运行。

## 基本角色

```text
Host（AI 应用）
  └─ Client（每个 Server 通常对应一个连接）
       └─ Server（暴露能力）
```

- Host 管理用户交互、模型、权限和多个客户端连接。
- Client 与某个 Server 协商协议版本和能力。
- Server 暴露工具、资源、提示模板等能力。

“把 M×N 集成降为 M+N”适合作为互操作愿景，但不是复杂度公式。认证、权限、宿主能力差异和产品交互仍可能需要适配。

## Tools、Resources 与 Prompts

| 原语      | 作用                                   | 常见控制方                          | 协议操作示例                       |
| --------- | -------------------------------------- | ----------------------------------- | ---------------------------------- |
| Tools     | 有类型输入输出的可调用操作，可读也可写 | 模型请求，Host 执行并可要求用户确认 | `tools/list`、`tools/call`         |
| Resources | 可寻址的上下文数据                     | 应用选择或按资源链接读取            | `resources/list`、`resources/read` |
| Prompts   | 可复用、可参数化的消息模板             | 用户显式选择                        | `prompts/list`、`prompts/get`      |

“谁控制”是推荐交互模型，而不是服务端可以绕过 Host 权限的保证。Host 最终负责展示、授权、调用策略和把结果加入模型上下文。

## 能力协商与版本

连接初始化时双方交换协议版本、实现信息和 capabilities。Server 不能假设客户端支持自己知道的全部功能；新增能力应通过协商检测，必要时提供降级路径。

协议按日期发布修订版，实验性能力可能变化。实现时应固定并记录 SDK 与协议版本，升级前阅读 changelog 和兼容说明。

## 标准传输

| 传输            | 适用情况                     | 注意事项                                                           |
| --------------- | ---------------------------- | ------------------------------------------------------------------ |
| `stdio`         | Host 启动本地 Server 子进程  | `stdout` 只能输出协议消息，日志写 `stderr`；进程权限等同本地风险面 |
| Streamable HTTP | 独立部署、远程或多客户端服务 | 单一 MCP 端点，可用 SSE 流式返回；需要认证、来源校验和会话管理     |

Streamable HTTP 已替代旧版 HTTP+SSE 传输。兼容旧客户端时要明确版本边界，不应把两套行为混写为同一种传输。

## 工具设计

一个好工具需要同时做到：

1. 名称稳定、单一职责，描述包含适用和不适用条件。
2. 用 JSON Schema 约束输入；能枚举就不要让模型猜自由文本。
3. 返回结构化结果并区分“调用协议失败”和“工具执行失败”。
4. 写操作尽量支持预览、幂等键和最小权限。
5. 错误信息可操作，但不泄露密钥、内部路径和敏感数据。

工具描述会影响模型的选择，但不能保证调用。需要强制执行的规则应由 Host 工作流或服务端验证落实，不能只依赖 prompt。

## 安全边界

- 把模型、工具参数和资源内容都视为不可信输入，校验长度、类型、范围和对象级权限。
- 高风险写操作在 Host 侧显示目标和影响，并要求明确确认。
- Server 不应透传客户端给自己的访问令牌到下游服务；令牌必须绑定正确受众。
- Streamable HTTP 校验 `Origin`，本地服务默认只监听 loopback，远程服务使用 HTTPS 和正确认证。
- 防止资源内容中的提示注入诱导模型越权；模型的“意图”不能替代服务端授权。
- 日志和遥测对敏感参数脱敏，设置审计记录与速率限制。

## 测试清单

- 初始化、版本不兼容、能力缺失时是否正确降级。
- schema 边界、超大输入、重复调用和并发调用。
- 超时、取消、断线重连与部分失败。
- 未授权用户、越权对象、恶意资源内容和 DNS rebinding 防护。
- 不同 Host 的展示、确认和资源读取行为差异。
