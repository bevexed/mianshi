# 映射类型进阶

## `as` 做 key remapping（TS 4.1+）

在映射时**重命名 key**：

```ts
// 生成 getter 名字
type Getters<T> = {
	[K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};
// { name: string } → { getName: () => string }

// 过滤 key（映射为 never 就会被丢弃）
type OmitByType<T, U> = {
	[K in keyof T as T[K] extends U ? never : K]: T[K];
};
type NoFunctions = OmitByType<{ a: string; fn: () => void }, Function>; // { a: string }

// 加前缀
type Prefixed<T, P extends string> = {
	[K in keyof T as `${P}${string & K}`]: T[K];
};
```

**内置的字符串工具类型**：`Uppercase` / `Lowercase` / `Capitalize` / `Uncapitalize`

## `keyof` / `typeof` / 索引访问的配合

```ts
const config = { host: 'a', port: 1 } as const;
type Config = typeof config; // 从值反推类型
type Keys = keyof Config; // 'host' | 'port'
type Port = Config['port']; // 1
```

### 从数组常量生成联合类型（业务里极其常用）

```ts
const STATUS = ['draft', 'pending', 'done'] as const;
type Status = typeof STATUS[number]; // 'draft' | 'pending' | 'done'
```

**为什么这个模式重要**：
一份常量既能在运行时遍历渲染下拉框，又能在类型层面约束，
**不用写两遍**——写两遍就一定会有一天不同步。

配合 `Record` 做映射：

```ts
const STATUS_LABEL: Record<Status, string> = {
	draft: '草稿',
	pending: '待审',
	done: '完成'
	// 少写一个就编译报错，加了枚举值也会提醒
};
```

## `as const` 做了什么

- 所有属性变 `readonly`
- 字面量类型**不被拓宽**（`'a'` 保持 `'a'` 而不是 `string`）
- 数组变成**只读元组**

```ts
const a = ['x', 'y']; // string[]
const b = ['x', 'y'] as const; // readonly ['x', 'y']
```

## 模板字面量类型

```ts
type EventName<T extends string> = `on${Capitalize<T>}`;
type Path = `/${string}`;

// 解析路由参数
type ExtractParams<S> = S extends `${string}:${infer P}/${infer Rest}`
	? P | ExtractParams<Rest>
	: S extends `${string}:${infer P}`
	? P
	: never;

type Params = ExtractParams<'/user/:id/post/:postId'>; // 'id' | 'postId'
```

这类能力让**字符串也能被类型系统约束**，
是 TS 4.1 之后类型体操题量暴增的原因。
