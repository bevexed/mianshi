# TypeScript 基础辨析

## interface 和 type 的区别

|              | interface                    | type                                                   |
| ------------ | ---------------------------- | ------------------------------------------------------ |
| 声明合并     | ✅ 同名会自动合并            | ❌ 重复定义报错                                        |
| 扩展         | `extends`                    | 交叉类型 `&`                                           |
| 能表达的类型 | 只能是对象/函数/类的形状     | **任意类型**——联合、元组、原始类型、条件类型、映射类型 |
| 性能         | 大型项目中检查略快（可缓存） | 复杂 type 可能拖慢编译                                 |

**实践建议**（有立场比背表格好）：

> 一种可执行的团队约定是：可能被声明合并或 `extends` 扩展的公共对象形状用
> interface；联合、元组、条件类型和工具类型用 type。组件 props 是否允许声明合并
> 需要团队主动决定，不应仅因为“对外暴露”就默认开放扩展。

**衍生问**：什么是声明合并？举个用途？
→ 给第三方库补充类型：

```ts
declare global {
	interface Window {
		myApp: MyAppSDK;
	}
}
```

## `extends` 有几种含义

**这题很能筛人，因为 `extends` 在 TS 里是重载的：**

1. **接口继承**：`interface A extends B {}`
2. **泛型约束**：`function f<T extends object>(x: T)`
3. **条件类型**：`T extends U ? X : Y`
4. **类继承**：`class A extends B {}`

## `unknown` / `any` / `never`

- **`any`**——大幅绕过类型检查，几乎可以和任何类型互相赋值（`never` 等有例外）。
  传染性强，能不用就不用
- **`unknown`**——**类型安全的 any**。任何值都能赋给它，
  但**用之前必须收窄**（类型守卫 / 断言）。
  接收未经验证的外部数据时应该把边界标为 `unknown`，再做收窄或运行时校验
- **`never`**——**永不存在的值**。函数永远不返回（抛错/死循环）、
  联合类型被排空后的结果

### never 的实用场景：穷尽性检查

```ts
function handle(s: 'a' | 'b') {
	switch (s) {
		case 'a':
			return 1;
		case 'b':
			return 2;
		default: {
			const _exhaustive: never = s; // 新增枚举值时这里会报错，提醒你补分支
			return _exhaustive;
		}
	}
}
```

**这个技巧一定要会**——它是 TS 在业务里最实用的价值之一：
当共享/生成的联合类型新增订单状态后，采用穷尽检查的 switch 会在编译期报错，
从而提醒补分支；如果前端类型没有同步更新，TypeScript 不会自动知道后端发生了变化。

## 类型收窄（Narrowing）的手段

```ts
typeof x === 'string'; // typeof 守卫
x instanceof Date; // instanceof 守卫
'key' in obj; // in 守卫
Array.isArray(x); // 内置守卫

// 自定义类型守卫
function isUser(x: unknown): x is User {
	return typeof x === 'object' && x !== null && 'id' in x;
}

// 可辨识联合（最推荐的建模方式）
type Result = { status: 'success'; data: string } | { status: 'error'; message: string };

if (res.status === 'success') res.data; // 自动收窄
```

**可辨识联合是 TS 建模业务状态的最佳实践**——
比 `{ data?: T; error?: E }` 这种可选字段的写法安全得多，
因为后者无法排除"两个都有"或"两个都没有"的非法状态。
