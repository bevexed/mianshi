## DeepPartial（被点名的高频题）

### 基础版

```ts
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K]
}
```

**这个版本有坑，能主动说出来才是加分**：
- 数组会被当成 object 递归，`string[]` 变成 `{ 0?: ..., length?: ... }`
- 函数也是 object
- `Date`、`Map`、`Set` 这类内置对象也会被拆开

### 完善版

```ts
type Primitive = string | number | boolean | bigint | symbol | null | undefined

type DeepPartial<T> =
  T extends Primitive ? T
  : T extends (...args: any[]) => any ? T
  : T extends Date | RegExp ? T
  : T extends Array<infer U> ? Array<DeepPartial<U>>
  : T extends ReadonlyArray<infer U> ? ReadonlyArray<DeepPartial<U>>
  : T extends Map<infer K, infer V> ? Map<K, DeepPartial<V>>
  : T extends Set<infer U> ? Set<DeepPartial<U>>
  : { [K in keyof T]?: DeepPartial<T[K]> }
```

> **面试策略**：先写基础版，然后**主动说**「这个版本对数组和内置对象处理得不对」，
> 再写完善版。主动指出自己方案的边界，比一次写对更能体现思维。

## 其他常考手写

```ts
// DeepReadonly
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K]
}

// 把指定 key 变可选，其余不变（业务里非常常用）
type PartialBy<T, K extends keyof T> = Omit<T, K> & Partial<Pick<T, K>>

// 反过来：把指定 key 变必填
type RequiredBy<T, K extends keyof T> = Omit<T, K> & Required<Pick<T, K>>

// 取出所有值为函数的 key
type FunctionKeys<T> = {
  [K in keyof T]: T[K] extends Function ? K : never
}[keyof T]

// 联合转交叉（利用逆变位置推断）
type UnionToIntersection<U> =
  (U extends any ? (x: U) => void : never) extends (x: infer I) => void ? I : never

// 数组转联合
type ElementOf<T extends readonly any[]> = T[number]

// 获取对象所有可能的值
type ValueOf<T> = T[keyof T]
```

### `FunctionKeys` 的模式值得单独记

**映射后用 `[keyof T]` 索引取出非 never 的 key**——
这个套路能实现"按条件筛选 key"：

```ts
// 通用版：按值类型筛 key
type KeysMatching<T, V> = {
  [K in keyof T]: T[K] extends V ? K : never
}[keyof T]

type StringKeys = KeysMatching<{ a: string; b: number }, string>  // 'a'
```

## 递归类型的注意点

- TS 有**递归深度限制**（约 50 层），
  深层递归会报 "Type instantiation is excessively deep"
- 尾递归优化在 TS 4.5+ 对**条件类型**有效
- 业务里如果需要超深递归，多半是类型设计有问题
