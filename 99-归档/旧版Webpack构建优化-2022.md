# 旧版 Webpack 构建优化（2022）

> 归档原因：原文以 `DllPlugin`、HappyPack 和合并文件为主，
> 不再适合当作现代 Webpack/Vite 项目的默认优化顺序。
> 当前版见 [构建优化](../08-性能优化/构建优化.md)。

从工程实践的角度，讨论前端优化

## 压缩与合并

资源的压缩与合并所涉及的优化点包括两个方面：

1. 减少 HTTP 的请求数量
2. 减少 HTTP 请求资源的大小

### HTML 压缩

通过删除 HTML 中对浏览器解析没有意义的字符，达到压缩的目的

### CSS 压缩

1. 删除无效代码
2. CSS 语义合并

### JavaScript 压缩与混淆

1. 无效字符和注释的删除
2. 代码语义缩减和优化
3. 代码混淆保护

### 文件合并

优点：减少了 HTTP 请求次数

缺点

1. 增加了 首屏渲染时间
2. 缓存失效导致合并文件大面积更新

建议

1. 合并公共库

## webpack 的性能优化

webpack 的优化瓶颈主要体现在两个方面：

1. 打包构建过程太浪费时间
2. 打包结构体积太大

### 尽量与时俱进

尽量保持 webpack 、 nodejs、 npm、yarn 等工具处于最新最稳定的版本

### 减少 Loader 的执行

1. 按需使用 include 和 exclude
2. 将构建结果缓存到文件系统中

### 合理使用 reslove 参数

减少打包时对目标文件的查找时间

### 使用 DllPlugin 插件

减少对第三方库的分析，加快打包速度

### 将单进程转化为多进程

webpack 是单进程的。可以使用插件（happypack）实现多进程。

### 压缩打包结果的体积

尽量减小打包后的体积

1. 删除冗余代码 Tree-shaking
2. 代码拆分按需加载

### 可视化分析

通过工具 webpack-bundle-analyzer 分析打包后的文件
