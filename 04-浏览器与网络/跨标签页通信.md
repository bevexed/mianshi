# 浏览器内多个标签页之间相互通信

## BroadcastChannel（现在的首选）

同源标签页间的广播，API 最简单：

```js
const ch = new BroadcastChannel('app')

// 发送
ch.postMessage({ type: 'logout' })

// 接收（不会收到自己发的）
ch.onmessage = e => {
  if (e.data.type === 'logout') location.href = '/login'
}

ch.close()  // 记得清理
```

**典型场景**：一个标签页退出登录，其他标签页同步登出；
一处改了主题/语言，全部同步。

## localStorage + storage 事件（老方案）

1. 在一个标签页使用 `localStorage.setItem()`
2. 在另一个标签页监听 `storage` 事件，从 `event` 对象里取信息

> Event 对象包含：`key`、`newValue`、`oldValue`、`url`、`storageArea`

**⚠️ 关键的坑**：`storage` 事件**不会在触发变化的那个页面里触发**，
只有其他同源页面能收到。很多人本地测试时以为没生效。

另一个问题：设置**相同的值不会触发**事件，
所以广播同一条消息两次时第二次收不到 → 需要加时间戳或随机数。

## 其他方案

### cookie + setInterval

1. 将需要传递的消息存在 cookie 中
2. 通过 `setInterval` 轮询获取 cookie

**已不推荐**——轮询有延迟且浪费性能，cookie 容量也小。

### SharedWorker

多个页面共享同一个 worker 实例，可实现多页面多线程通信。
能力最强但兼容性和调试成本较高（Safari 曾长期不支持）。

### WebSocket

全双工，但这是**通过服务端中转**——
同源标签页通信用它属于杀鸡用牛刀，
除非本来就有长连接且消息需要跨设备同步。

---

## 选型建议

| 场景 | 方案 |
|---|---|
| 同源标签页广播（登出、主题切换） | **BroadcastChannel** |
| 需要兼容老浏览器 | storage 事件 |
| 需要共享计算/连接 | SharedWorker |
| 跨设备同步 | WebSocket（本质是服务端推送，不算标签页通信） |
