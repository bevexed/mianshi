## 两种实现路线

| | HTML5 Drag and Drop API | 鼠标/触摸事件模拟 |
|---|---|---|
| 实现 | `draggable` + `dragstart`/`dragover`/`drop` | `mousedown`/`mousemove`/`mouseup` |
| 优点 | 原生支持跨窗口、跨应用拖拽文件 | **完全可控**，动画自由 |
| 缺点 | **样式难定制**（拖拽影像）、**移动端不支持** | 要自己处理边界、滚动 |
| 适用 | 文件上传、跨应用 | **应用内排序、拖拽布局** |

**结论**：应用内的拖拽排序，
主流库（react-dnd、dnd-kit、sortablejs）**基本都走事件模拟路线**，
因为 HTML5 API 在移动端不可用。

## HTML5 Drag and Drop

```js
// 拖拽源
el.draggable = true
el.addEventListener('dragstart', e => {
  e.dataTransfer.setData('text/plain', id)
  e.dataTransfer.effectAllowed = 'move'
})

// 放置目标
target.addEventListener('dragover', e => {
  e.preventDefault()          // ⭐ 必须阻止默认行为，否则 drop 不触发
  e.dataTransfer.dropEffect = 'move'
})
target.addEventListener('drop', e => {
  e.preventDefault()
  const id = e.dataTransfer.getData('text/plain')
})
```

### 两个必踩的坑

1. **`dragover` 里必须 `preventDefault()`**——
   否则 `drop` 事件根本不会触发。这是最经典的坑
2. **`dragenter`/`dragleave` 会因子元素冒泡而反复触发**——
   鼠标移到子元素上会先触发子元素的 enter 再触发父元素的 leave，
   导致高亮闪烁
   → 解法：用计数器，enter 加一 leave 减一，归零才算真正离开

## 事件模拟方案

```js
let startX, startY, dragging = false

el.addEventListener('mousedown', e => {
  startX = e.clientX; startY = e.clientY
  dragging = true
  // ⭐ 监听挂在 document 上，否则鼠标移出元素就丢失
  document.addEventListener('mousemove', onMove)
  document.addEventListener('mouseup', onUp)
})

function onMove(e) {
  if (!dragging) return
  const dx = e.clientX - startX
  const dy = e.clientY - startY
  // ⭐ 用 transform 而不是 left/top，避免触发重排
  el.style.transform = `translate(${dx}px, ${dy}px)`
}

function onUp() {
  dragging = false
  document.removeEventListener('mousemove', onMove)
  document.removeEventListener('mouseup', onUp)   // ⭐ 必须清理
}
```

### 关键细节

1. **监听挂 document 而非元素本身**——
   鼠标移动快时会移出元素范围，挂元素上会丢事件
2. **用 `transform` 不用 `left/top`**——
   transform 只触发合成，不触发重排重绘
3. **阈值判断**——移动超过 3-5px 才算拖拽，
   否则会把点击误判成拖拽
4. **移动端要用 `touchstart`/`touchmove`/`touchend`**，
   且 `touchmove` 里要 `preventDefault()` 阻止页面滚动
   （注意 passive 监听器的问题）

## 拖拽排序的核心算法

**难点不是"拖起来"，是"放哪里"。**

```
1. 拖拽中，实时计算指针位置落在哪个元素的区间
2. 判断应该插入到目标元素之前还是之后
   → 看指针是在目标元素的上半部分还是下半部分
3. 显示占位符（placeholder）指示落点
4. 释放时更新数据顺序，重新渲染
```

**性能要点**：
- `mousemove` 触发频率极高，
  位置计算要用 `requestAnimationFrame` 节流
- 元素位置（`getBoundingClientRect`）**缓存起来**，
  别在每次 move 里重新读——会触发强制同步布局

> 强制同步布局（layout thrashing）见
> [重排和重绘.md](重排和重绘.md)

## 其他要处理的场景

| 场景 | 处理 |
|---|---|
| **拖到边缘自动滚动** | 检测指针接近容器边缘，用 rAF 循环滚动 |
| **跨列表拖拽** | 需要统一的拖拽上下文管理状态 |
| **虚拟滚动 + 拖拽** | 很难——拖拽目标可能不在 DOM 里 |
| **拖拽时的动画** | FLIP 技术（记录 First/Last 位置，用 transform 做 Invert 再 Play） |

## 库的选型

- **react-dnd**——抽象度高（基于 HTML5 backend 或 touch backend），
  概念多（DragSource/DropTarget），学习曲线陡
- **dnd-kit**——现代替代品，
  无 HTML5 API 依赖、支持触摸和键盘、可访问性好
- **sortablejs**——非框架相关，排序场景开箱即用
