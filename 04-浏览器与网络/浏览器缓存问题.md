# HTTP 缓存：强缓存与验证缓存

## 1. 有新鲜度时直接复用

服务端用 `Cache-Control`（优先）或 `Expires` 声明响应的新鲜期：

```http
Cache-Control: public, max-age=31536000, immutable
```

在允许复用且仍新鲜时，浏览器通常不向源站验证。`Expires` 是绝对时间，
容易受时钟影响；`Cache-Control: max-age` 是相对秒数。

常见指令：

- `no-store`：不要存储响应。
- `no-cache`：可以存，但每次复用前必须验证；**不是“不缓存”**。
- `private`：只允许私有缓存，不给共享 CDN 缓存。
- `s-maxage`：共享缓存的新鲜期。

## 2. 过期后向服务端验证

```http
ETag: "content-hash"
Last-Modified: Tue, 21 Jul 2026 02:00:00 GMT
```

浏览器可发送 `If-None-Match` / `If-Modified-Since`。资源未变化时服务端返回 304，
浏览器继续使用本地响应体；变化则返回新的 200 响应。

同时存在时通常优先 ETag 条件。`Last-Modified` 精度和语义有限，ETag 也不一定是
内容哈希，只要服务端能用它判断选定表示是否变化即可。

## 工程实践

- 带内容 hash 的静态资源：长期 `max-age` + `immutable`。
- HTML 入口：短缓存或每次验证，确保能及时引用新 hash 资源。
- 用户私有响应谨慎使用 `public`，并正确设置 `Vary`，避免共享缓存串数据。
