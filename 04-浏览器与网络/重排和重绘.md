# 样式、布局、绘制与合成

浏览器渲染可简化为：样式计算 → 布局（layout）→ 绘制（paint）→ 合成（composite）。
实际引擎会增量处理、跳过阶段或合并工作，不是每次都完整重跑。

## 布局（常被称为重排/回流）

布局计算元素几何位置和尺寸。以下变化常需要重新布局：

- 增删可见 DOM。
- 改变宽高、padding、border、字体、内容或布局模式。
- viewport 尺寸变化。

布局变化通常会让受影响区域重新绘制，但影响范围取决于布局树和 containment，
不能概括成整页必然重排。

## 绘制

颜色、阴影、背景等视觉变化可能只需要重新绘制，不改变几何位置。
绘制结果随后被分层并合成到屏幕。

`transform` 和 `opacity` 动画在元素已进入合适合成层时通常可以避免布局，
并可能避免主线程绘制；是否创建图层由浏览器决定，`will-change` 也不能滥用，
否则会增加显存和合成成本。

## 强制同步布局（layout thrashing）

写入样式后立刻读取几何属性，浏览器可能为了给出最新值而同步刷新布局：

```js
// 容易反复触发布局
for (const item of items) {
	item.style.width = '100px';
	console.log(item.offsetWidth);
}

// 先批量读，再批量写
const widths = items.map((item) => item.offsetWidth);
items.forEach((item, index) => {
	item.style.width = `${widths[index] + 10}px`;
});
```

常见会要求最新布局的 API 包括 `getBoundingClientRect()`、offset/client/scroll 尺寸、
`getComputedStyle()` 的部分属性等，具体是否强制刷新取决于此前是否有待处理样式变化。

## 优化原则

- 批量读、批量写，避免循环里交替读写布局。
- 用 class 切换集中样式变化；大量 DOM 插入可先在脱离文档的结构中组装。
- 动画优先 transform/opacity，并用 `requestAnimationFrame` 对齐帧。
- 大组件可评估 `contain`、`content-visibility`，但要验证布局和可访问性影响。
- 先用 Performance 工具定位 Layout/Paint/长任务，再优化，不要为了“零重排”牺牲代码清晰度。
