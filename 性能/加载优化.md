# 加载优化

想要得到更好的性能体验，仅靠资源压缩和恰当的文件格式选型，很难满足期望的。

我们还需要对**资源加载过程**进行优化该环节所做的内容包括

1. 分清资源加载的优先顺序
2. 仅加载当前所必须的资源
3. 利用空闲系统提前加载可能会用到的资源

## 延迟加载
通过延迟加载**非关键**内容，使页面内容更快速的呈现在用户面前。

### 图像延迟加载
相对于文本、脚本等其他资源，图片资源的大小不容小觑

#### 传统方式
通过监听 `scroll`和`resize`事件，并在回调事件中判断需要进行延迟加载的图片是否进入视窗区域

#### Intersection Observer
通过 Intersection Observer API 检测目标元素的可见性

+ 性能好和效率高
+ 有兼容问题
+ 使用时使用 polyfill 垫片进行兼容

#### CSS 类名方式
通过 CSS 的 background 属性加载图片。

1. 涉及外部请求的CSS规则在当前文档中不存在时，不会请求该资源。
2. 需要结合 JS 判断

### 原生的延迟加载支持
Chrome 75 后原生支持 img 标签的延迟加载

1. 有兼容问题，不稳定

## 视频加载
浏览器会对视频资源进行预加载

### 不需要自动播放
为了更快的加载并渲染页面，可以阻止不需要自动播放的视频预加载

### 视频代替GIF动画
+ 通过 poster 属性占位
+ 使用 js 进行 延迟加载

## 加载注意事项
延迟加载需要JavaScript介入，必定会对性能照成影响

### 首屏加载
1. 首屏上的内容不应使用延迟加载
2. 渲染设备的大小不可控，建议设置一个延迟加载的缓存区

### 资源占位
延迟的媒体资源未渲染出来之前应该使用占位图。

如果不使用占位符，图像延迟加载后会使页面布局出现位移

占位符类型：

+ Base64
+ LQIP（低质量图片占位符）
+ SQIP（基于SVG的LQIP）

对于媒体资源标签应该添加**width**和**height**属性，防止最终媒体资源加载时，发生元素渲染大小的改变

### 内容加载失败
媒体加载失败时应该做出相应的处理，以提高用户体验

### 图像解码延迟
图像从被浏览器请求，到最终渲染到屏幕上，需要一个解码时间。这个解码过程会占用浏览器的主进程，导致用户界面出现短暂的无响应。

可以使用 decode 方式延迟解码（有兼容问题）

> 图片很小的时候不建议使用
>

### JavaScript 是否可用
以上所有优化都是默认 JAvaScript 可用下完成的。当 JAvaScript 不可用时，需要做好适配

```html
<!-- 当 JavaScript 不可用时，会展示该部分-->
<noscript>
  <img/>
</noscript>
```

## 资源优先级
浏览器向网络发送请求时，并非每个字节都具有相同的优先级和重要性。浏览器会采取启发式算法，加载的顺序一般为：

1. 先加载css文件
2. 后加载 JavaScript 脚本文件和图像文件

### 优先级
分位四个等级：**Lowest**、**Low**、**High**、**Height**

### 预加载
```html
<!-- 通过 preload 强制浏览器进行预加载  -->
<link rel='preload'/>
```

### 预连接
在速度较慢的网络环境中建立链接非常耗时，这时可以采用预连接的方式优化。

```html
<!-- 不建议使用 -->
<link rel='preconnect' href=''/>
<!-- dns预解析 建议使用这个 -->
<link rel='dns-prefetch' href=''/>
```

### 预提取
根据用户行为判断接下来的操作，告知浏览器提前加载内容。

1. 预提取不会降低现有资源的优先级
2. 预提取不能递归使用

```html
<link rel='dns-prefetch' href=''/>
```

> 因为缓存等问题，使用时应该充分考虑
>
